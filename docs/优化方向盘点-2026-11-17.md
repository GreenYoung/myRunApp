## 1. 仍存在的高优先级问题（建议先修）

### 1.1 跑步中暂停仍保持 GPS 定位（耗电）

`RunTrackingService.pauseTracking()`（`RunTrackingService.kt:258-278`）只做了 `isPaused = true` + 释放 wakelock，**没有停止定位**；AMap 客户端仍按 1s 间隔回调，`handleLocation()` 里再丢弃（`:640`）。

- 影响：暂停 10 分钟的间歇训练会白耗 10 分钟高精度定位；日志也在持续写盘。
- 建议：暂停时 `stopLocationUpdates()`，恢复时重启并沿用已有的"跳过首个点"基线逻辑（`skipNextAcceptedPoint` + `gpsTrackFilter.reset()` 已支持）。
- 成本：小（约 10 行），风险低。

### 1.2 跑步时长依赖系统墙上时钟

`activeDurationSeconds()`（`RunTrackingService.kt:829-832`）用 `System.currentTimeMillis()` 计算，改时间 / NTP 校时 / 跨时区会让时长跳变甚至归零。

- 建议：计时改 `SystemClock.elapsedRealtime()`，展示时再与墙上时间（起点时刻）分离；`startTime` 仍需保留用于落库。
- 成本：中（涉及 draft 字段与恢复逻辑）。

### 1.3 通知权限被拒 → 完全不能开始跑步

`RunTrackingScreen.kt:65-70` 与 `:67` 的判断把 `hasNotificationPermission` 和定位权限并列阻断；Android 13+ 前台服务本身不依赖通知权限。

- 建议：改为"警告 + 仍可开始"，或在设置页提供显式开关。
- 成本：小。

### 1.4 进行中的跑步没有"放弃"入口

当前只有恢复草稿场景有 `onDiscardRecoveredDraft`；跑步进行中（`isTracking = true`）只有暂停/继续、长按结束保存，跑错了只能保存或一直挂着。

- 建议：跑步 HUD 增加"结束并放弃"（二次确认），调用已有的 `ACTION_DISCARD` / `discardTracking()`。
- 成本：小（服务端能力已有，缺 UI 与确认弹窗）。

### 1.5 体重目标只支持"减重"

`calculateTargetProgress`（`WeightLogic.kt:192-198`）在 `target >= firstWeight` 时直接返回 `null`，增重目标会显示"未设置"；`calculateRemainingWeight` 被夹到 0 后又会显示"已达成"。

- 建议：按方向计算（`abs(target - first)` 作为总量），文案按实际与目标的大小关系切换"还需减/还需增"。
- 成本：小（纯逻辑 + 1 处文案 + 单测）。

### 1.6 体重编辑换日期会覆盖同日记录且无提示

`WeightViewModel.saveWeight()`（`WeightViewModel.kt:289-303`）在目标日期已有记录时直接 upsert，用户原数据被静默覆盖（事务已加，但覆盖语义未处理）。

- 建议：目标日期已存在记录时弹"合并/取消"；或明确产品规则（同日只允许一条 + 覆盖前确认）。
- 成本：小~中。

## 2. 中优先级：一致性与健壮性

### 2.1 全局字距 0.5sp（本轮已踩坑两次）

`Typography.bodyLarge.letterSpacing = 0.5.sp`（`Type.kt:16`）会被所有 `Text` 继承——本轮「时长 · 配速 · 热量」那行 28 个字符因此多占约 14dp，配速多一位就把 `kcal` 挤掉；分段按钮的文字同样偏松。

- 建议（二选一）：
  1. 把 `bodyLarge.letterSpacing` 改为 `0.sp`，重新过一遍视觉；
  2. 新增 `NumericText = TextStyle(fontFeatureSettings = "tnum", letterSpacing = 0.sp, lineHeight = 16.sp)`，所有"数值 + 单位"文本统一用它（现在的 `ExerciseTabularNumbers` 只设了 tnum）。
- 收益：一次性消除"多一个数字就溢出"的一类问题。

### 2.2 全局 ripple 实际不可见

项目里大量 `Box(...).background(...).clickable { }`（首页卡片、记录行、分段按钮、统计卡等）。`clickable` 默认 ripple 取 `LocalContentColor`，而裸 `Box` 不是 `Surface`，取到的是**默认黑色** → 深色背景上按下几乎没有反馈。

- 建议：抽 `Modifier.appClickable(onClick, pressedAlpha = ...)`：统一 ripple 颜色（或按下态背景）+ `interactionSource`，并顺带保证最小触控尺寸（48dp）。
- 参考：本轮分段按钮已经用"按下态背景"绕开（`ExerciseScreen.kt` 的 `ExerciseStatsSegment`），可复用同一套。

### 2.3 单行文本没有溢出兜底

多处只有 `maxLines = 1`、没设 `overflow`（默认 `Clip`），超宽就静默吞掉尾部，用户只看到"信息少了"，看不到"…"。

- 建议：定义文本策略——
  - 数值型单行：`softWrap = false` + 允许缩字号或分两段；
  - 说明型单行：`overflow = TextOverflow.Ellipsis`；
  - 关键不再丢失的信息（如热量）拆成不可压缩的独立 `Text`。
- 重点位置：记录行元信息、月卡头部「累计 N 次 · X 小时」、统计详情卡 subline。

### 2.4 地图页状态不保存

`RunTrackingScreen.kt:127-128` 的 `mapDisplayType` / `autoFollow` 与 `RunTrackDetailScreen.kt:58`、`ExerciseRecordDetailScreen.kt:99` 的 `mapDisplayType` 都是 `remember`，旋转/重建即重置；`MapView` 也未走 `onSaveInstanceState`。

- 建议：改 `rememberSaveable`（枚举可保存）；MapView 按官方流程保存/恢复。

### 2.5 postDelayed 无销毁保护

`AMapRunTrackingMap.kt:286-289` 的 `mapView.postDelayed { moveToCurrentLocation(...) }` 在页面退出后仍可能执行，存在对已销毁 MapView 操作的偶发崩溃风险。

- 建议：`DisposableEffect` 维护 `destroyed` 标志，post 前后判空；或在 `onDispose` 里 `mapView.removeCallbacks(...)`。

### 2.6 权限检查读到旧快照

`RunTrackingScreen.kt:65-70`：`LaunchedEffect(Unit)` 里先 `refreshPermission()`，随后判断用的仍是进入组合时的 `uiState` 快照 → 权限已授予也可能再弹一次。

- 建议：把判断移到 ViewModel（`refreshPermission()` 返回结果），或用 `rememberUpdatedState` / `snapshotFlow` 读最新值。

### 2.7 地图交互细节

- 通知小图标仍是 `R.mipmap.ic_launcher`（`RunTrackingService.kt:991`），状态栏可能显示空白方块；建议加专用单色 `ic_stat_run`。
- `SwipeBackContainer`（`:35`）的 `pointerInput(onBack)` key 每次重组都变，手势可能被打断；建议 `rememberUpdatedState`。
- 两处 `LocalLifecycleOwner` 仍是弃用 API（`AMapRunTrackingMap.kt:66`、`AMapTrackPreview.kt:36`），升级到 `lifecycle-runtime-compose` 即可消警。

### 2.8 主题与启动

`themes.xml:5` 的父主题是 `android:Theme.Material.Light.NoActionBar`，而 UI 是纯深色：

- 冷启动可能出现白色 windowBackground 闪一下；
- 系统栏图标颜色依赖 `enableEdgeToEdge()` 的"跟随系统深色"策略，与 App 内部固定深色不完全一致。
- 建议：换深色父主题，或引入 SplashScreen API 统一启动样式。

### 2.9 浅色主题目前是"占位实现"

`Theme.kt:24-36` 的 `LightColorScheme` 取值与深色完全相同（只是把同一个 `darkColorScheme` 换成了 `lightColorScheme` 工厂，颜色仍然写死深色值），且 `MainActivity` 固定 `MyRunAppTheme(darkTheme = true)`，`isSystemInDarkTheme()` 实际未生效。

- 结论：现在**不存在真正的浅色模式**；如果产品需要，必须先做一套浅色 token（而不是改一个开关）。
- 顺带：`MyRunAppTheme` 没有提供 `LocalContentColor`，这也是 2.2 里 ripple 取到黑色的直接原因之一。

## 3. 性能

### 3.1 轨迹点 O(N²) 追加（最值得修的一条）

`RunTrackingService.handleLocation()`（`RunTrackingService.kt:669`）：

```kotlin
val points = current.trackPoints + result.point          // 每次复制整个列表
RunTrackingStateStore.update { current.copy(trackPoints = points) }
```

- 每秒一次，跑 2 小时 ≈ 7200 点 → 累计约 **2600 万次**元素复制，且每次触发 StateFlow 全量通知、Compose 侧重组；
- 尾段渲染已经是增量（`AMapLiveTrackRenderer`），但状态层仍是全量。

建议：改用可持久化的结构（`SnapshotStateList` / 不可变链表 / 每 100 点一个 chunk 的 `List<List<Point>>`），或 HUD 只订阅"数量 + 最后一点"的派生状态。

### 3.2 结束时一次性插入全部轨迹点

`saveRun()`（`:628`）单事务插入 2 万行，中低端机可能数百毫秒并卡 UI 收尾动画；建议分批（如 1000 行/批）或 `insertAll` + 事务拆分（记录/会话一事务，轨迹点分批）。

### 3.3 统计详情翻页重复全量查询

`ExerciseViewModel.observeStatsDetail()` 每次 `periodOffset` 变化都重新 `observeAllExercises().map { buildExerciseStatsDetail(...) }`；翻页快时会有重复聚合。建议缓存最近 N 期结果，或按 period 拆分 Room 查询（`WHERE startTime BETWEEN`）。

### 3.4 地图重复配置

`AMapTrackPreview` 的 `update` 每次都执行 `configureSportTrackUi`（`setMapType` 等），而它只在 `mapDisplayType` 变化时才需要。建议加按状态的 `remember` 判断。

### 3.5 日志量

GPS 每秒多条 D 级日志 + 坐标明文；文件写入已异步（`FileLogWriter`），但 release 仍开启（见 4.3）。建议 release 关文件日志或加"诊断模式"开关，并对坐标做截断。

- 仓库没有 `.github`，构建、单测、lint 全手动；
- `app/src/androidTest` 只有模板（`ExampleInstrumentedTest`），Compose UI 测试依赖已引入但未使用；

建议：GitHub Actions 跑 `assembleDebug + testDebugUnitTest + lint`；再加 3~5 条 Compose UI 冒烟（首页、记录列表、统计详情翻页）。

### 4.4 大文件

`RunTrackingService` 1140 行、`WeightTrendScreen` 661、`RunTrackingHud` 593、`AMapRunTrackingMap` 557、`WeightScreen` 552。建议：服务拆分（定位/计时/草稿/通知），页面拆分（图表 / 卡片 / 弹窗）。

### 4.5 文案与国际化

`res/values/strings.xml` 只有 `app_name`，其余文案全部硬编码在 Kotlin：

- 无法做多语言，也无法统一术语（"运动/跑步/记录"混用）；
- 文案改动需要改代码 + 重新编译。

建议：至少把"会被复用的术语"（类型名、单位、空状态、错误提示）抽到 `strings.xml`。

### 4.6 设计 token 分散

同一语义多种取值：卡片背景（`ExerciseCardTop/Bottom`、`HomeGreen`、`StatsHeroTop`）、分割线（`0x14FFFFFF`、`0x0DFFFFFF`）、圆角（14/20/22/24）、间距（12/14/16/18）。

建议：收敛到 `ui/theme/Tokens.kt`（颜色、圆角、间距、字号），各 feature 只引用 token。
