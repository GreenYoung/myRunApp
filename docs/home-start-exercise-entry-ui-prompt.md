# 首页开始运动入口 UI 设计实现提示词

请基于当前 Android 项目，后续优化首页结构，在首页增加一个「开始运动」主入口。

本提示词只用于后续实现规划。当前不要修改体重记录、运动记录、趋势图、目标设置、编辑删除等已经完成的业务功能。

## 1. 当前背景

当前首页已有：

```text
HomeScreen
WeightSummaryCard
ExerciseSummaryCard
```

目前首页主要展示：

```text
体重卡片
运动卡片
```

后续需要增加一个更强的运动启动入口，让用户打开 APP 后第一眼可以开始运动，整体体验参考悦跑圈一类运动 APP。

## 2. 首页信息层级目标

首页调整为“三段式”结构：

```text
顶部标题
↓
开始运动卡片
↓
今日运动卡片
↓
今日体重卡片
```

信息优先级：

```text
开始运动
今日运动状态
今日体重状态
历史累计 / 目标进度
```

整体原则：

- 首页第一优先级是“开始运动”。
- 运动类 APP 的主行为入口要明显。
- 今日运动和今日体重继续保留，但作为复盘和记录状态展示。
- 不要把首页做成营销页。
- 不要堆砌过多文字说明。
- 继续使用 Jetpack Compose 实现。

建议首页布局：

## 4. 开始运动卡片

建议新增组件：

```kotlin
@Composable
fun StartExerciseCard(
    onStartClick: () -> Unit,
    onOutdoorClick: () -> Unit,
    onTreadmillClick: () -> Unit,
    onFreeRunClick: () -> Unit
)
```

如果第一版还不实现真实 GPS 跑步功能，可以先只提供视觉入口：

```text
点击开始运动
↓
进入运动详情页
```

或者：

```text
点击开始运动
↓
打开增加运动记录弹窗
```

具体行为后续实现时再确认。

## 5. 开始运动卡片视觉

卡片风格：

```text
深色运动风
绿色强调色
轻微渐变
克制层叠背景
圆角 20dp
高度建议 220dp～260dp
```

建议主视觉：

```text
中间一个绿色圆形主按钮
按钮内显示 ▶ 或 RUN
```

示意：

```text
┌──────────────────────────────┐
│ 开始运动                      │
│                              │
│          ┌────────┐          │
│          │   ▶    │          │
│          │  RUN   │          │
│          └────────┘          │
│                              │
│   户外跑步     跑步机     自由跑 │
└──────────────────────────────┘
```

要求：

- 主按钮是首页最显眼的可点击元素。
- 不使用系统默认按钮样式。
- 不使用白色大面积背景。
- 不使用复杂动画。
- 可以使用 Compose Canvas 绘制轻量运动弧线或速度线。
- 不引入新的大型 UI 库。

## 6. 模式入口

开始运动卡片底部放 2～3 个轻量模式入口。

建议第一版：

```text
户外跑步
跑步机
自由跑
```

要求：

- 不要做成过重的小卡片。
- 可以使用图标 + 文字。
- 选项之间间距均匀。
- 点击行为第一版可以统一进入运动详情页或打开增加运动记录弹窗。
- 后续 GPS 功能实现后，户外跑步再接 GPS 记录。

## 7. 今日运动卡片调整

当前 `ExerciseSummaryCard` 已经展示今日运动、周/月目标、连续打卡等信息。

后续首页新增开始运动卡片后，`ExerciseSummaryCard` 可以适当降低视觉重量：

- 保留今日距离主视觉。
- 保留今日是否已打卡。
- 保留本周还差多少 km。
- 保留月完成百分比。
- 保留连续打卡天数。
- 历史累计信息不要抢开始运动入口视觉。

如果首页垂直空间不够，可以减少 `ExerciseSummaryCard` 内部辅助指标数量。

## 8. 今日体重卡片调整

`WeightSummaryCard` 继续作为第三段展示。

要求：

- 今日体重仍是主视觉。
- 今天未记录时展示 `--.-- kg`。
- 最新体重作为辅助信息展示。
- 点击仍进入体重详情页。

## 9. 首页顶部区域

顶部建议：

```text
每日运动              08月26日
今天也动起来
```

要求：

- 不要占用过多高度。
- 与当前顶部安全区规则保持一致。
- 不要破坏之前已经统一过的顶部间距。

## 10. 架构要求

HomeScreen 只负责组合页面。

建议拆分：

```text
HomeScreen
 ├── HomeHeader
 ├── StartExerciseCard
 ├── ExerciseSummaryCard
 └── WeightSummaryCard
```

不要把开始运动卡片所有绘制逻辑全部塞进 HomeScreen。

## 11. 适配要求

优先适配当前目标设备：

```text
荣耀 MAGIC8
```

同时控件尺寸要支持后续设备更换。

要求：

- 使用 `fillMaxWidth()`。
- 不写死屏幕宽度。
- 通过 padding、weight、Arrangement、Alignment 做响应式布局。
- 文本不要溢出。
- 小屏幕下可以压缩辅助信息，但主按钮不能被挤压。

## 12. 推荐实现顺序

建议后续按以下步骤实现：

```text
1. 检查当前 HomeScreen / ExerciseSummaryCard / WeightSummaryCard
2. 新增 StartExerciseCard 组件
3. 实现深色运动风背景
4. 实现绿色圆形 RUN 主按钮
5. 实现户外跑步 / 跑步机 / 自由跑入口
6. 调整 HomeScreen 顺序为：开始运动、今日运动、今日体重
7. 保持点击运动卡片进入运动详情页
8. 保持点击体重卡片进入体重详情页
9. 编译验证
10. 检查首页不同状态：有今日运动、无今日运动、有今日体重、无今日体重
```

## 13. 验收标准

最终首页应满足：

- 第一眼能看到“开始运动”入口。
- 开始运动按钮视觉最突出。
- 页面仍然是深色年轻运动风。
- 运动卡片和体重卡片仍然保留。
- 首页顺序为：开始运动、今日运动、今日体重。
- 不破坏现有运动详情页和体重详情页导航。
- 不引入大型第三方 UI 框架。
- 不实现 GPS 跑步，除非后续单独提出。
- Compose 代码结构清晰。
