# 趋势图拆分与目标体系增强 实现提示词

请基于当前 Android 项目，后续分阶段优化体重趋势图模块和运动目标体系。

本提示词只用于后续实现规划，不要求一次性完成所有功能。实现时必须控制范围，优先保证当前已经完成的体重记录、运动记录、首页卡片、运动详情页等功能不被破坏。

## 1. 当前背景

当前项目已有：

```text
首页体重卡片 WeightSummaryCard
体重详情页 WeightDetailScreen
体重记录新增 / 编辑 / 删除
体重曲线展示
运动首页卡片 ExerciseSummaryCard
运动详情页 ExerciseDetailScreen
运动记录新增 / 编辑 / 删除
运动目标设置：周运动里程、月运动里程
Room + Flow + ViewModel 状态刷新
Jetpack Compose + Material 3
```

目前体重曲线逻辑已经较复杂，后续需要从体重详情页中进一步拆分为独立全屏图表模块。

目前运动目标只支持周/月里程，后续可以增强目标展示和提醒，但不要一次加入过多目标类型。

## 2. 总体目标

后续优化分为两个方向：

```text
方向一：体重趋势图拆分
方向二：运动目标体系增强
```

实现时建议分两个独立任务推进，避免趋势图交互和运动目标逻辑互相影响。

## 3. 方向一：体重趋势图拆分

### 3.1 目标

将当前体重曲线拆成独立全屏图表模块。

建议新增：

```text
WeightTrendScreen
WeightTrendChart
WeightTrendRangeSelector
WeightTrendUiState
```

体重详情页中可以保留一个简洁入口，例如：

```text
查看体重趋势
```

点击后进入独立趋势图页面。

### 3.2 筛选范围

趋势图统一支持：

```text
7 天
30 天
90 天
全部
```

范围定义：

```text
7 天：最近 7 天记录
30 天：最近 30 天记录
90 天：最近 90 天记录
全部：全部体重记录
```

筛选切换后，图表和统计信息立即刷新。

### 3.3 横屏全屏

趋势图页面必须支持：

```text
竖屏普通展示
横屏全屏展示
```

要求：

- 横屏时图表尽量铺满屏幕。
- 横屏时减少无关文字和装饰。
- 横屏时仍保留必要的返回或关闭入口。
- 不允许内容进入系统状态栏或导航栏。
- 不要因为横竖屏切换导致图表状态丢失。

### 3.4 点选查看具体记录

趋势图支持点击或拖动点选数据点。

选中某个体重点后展示：

```text
日期
体重
较上次变化
```

示例：

```text
08-25
77.40 kg
较上次 -0.40 kg
```

交互要求：

- 点选状态要清晰。
- 选中点可以使用绿色高亮。
- 未选中点保持低干扰。
- 弹出的信息不要遮挡关键曲线。
- 没有数据时展示合理空状态。

### 3.5 目标体重线

趋势图增加目标体重线。

要求：

- 如果用户已设置目标体重，则显示一条目标线。
- 目标线颜色使用当前 APP 绿色或低透明度绿色。
- 目标线需要有简洁标签，例如：

```text
目标 72.00 kg
```

- 如果没有目标体重，不显示目标线。
- 不要为了目标线修改已有体重记录数据库结构，优先复用现有目标体重状态。

### 3.6 数据与架构要求

UI 不直接查询数据库。

建议数据流：

```text
Room / Repository
   ↓
ViewModel
   ↓
WeightTrendUiState
   ↓
WeightTrendScreen
```

Composable 只负责渲染，不负责复杂统计计算。

### 3.7 验收标准

最终趋势图模块应满足：

- 独立页面承载复杂体重曲线。
- 支持 7 天 / 30 天 / 90 天 / 全部。
- 支持横屏全屏。
- 支持点选查看具体记录。
- 支持目标体重线。
- 无数据状态明确。
- 竖屏比例和样式稳定。
- 不影响首页体重卡片的简洁展示。

## 4. 方向二：运动目标体系增强

### 4.1 目标

在当前周/月运动里程目标基础上，增强目标完成状态展示。

本阶段只考虑以下能力：

```text
目标完成提醒
本周还差多少 km
月目标完成百分比
连续打卡天数
```

不要新增以下复杂目标：

```text
卡路里目标
运动时长目标
每日目标
运动次数目标
AI 推荐目标
GPS 目标
```

### 4.2 目标完成提醒

当周目标或月目标完成时，页面可以展示轻量提醒。

示例：

```text
本周目标已完成
本月目标已完成
```

要求：

- 提醒要克制，不使用打断式弹窗。
- 可以放在首页运动卡片或运动详情页顶部。
- 不要重复频繁弹出。
- 不影响用户继续添加运动记录。

### 4.3 本周还差多少 km

基于当前周目标和本周累计里程计算：

```text
remainingWeeklyKm = weeklyGoalKm - weeklyDistanceKm
```

展示规则：

- 如果还未完成：显示 `本周还差 xx.xx km`。
- 如果已完成：显示 `本周目标已完成`。
- 固定保留两位小数。
- 不允许显示负数距离。

### 4.4 月目标完成百分比

基于当前月目标和本月累计里程计算：

```text
monthlyProgressPercent = monthlyDistanceKm / monthlyGoalKm * 100
```

展示规则：

- 显示为整数百分比，例如 `66%`。
- 展示进度最大限制为 `100%`。
- 原始完成情况可以超过 100%，但 UI 进度条或圆环不要溢出。
- 月目标为 0 或非法值时，回退到默认目标或展示空状态。

### 4.5 连续打卡天数

根据运动记录日期计算连续打卡天数。

建议规则：

- 同一天多条记录只算 1 天。
- 如果今天有运动记录，则从今天往前连续计算。
- 如果今天没有记录但昨天有记录，可以根据产品定义选择是否从昨天开始计算。
- 为了鼓励用户，建议采用：

```text
今天有记录：从今天开始计算连续天数
今天无记录：从昨天开始计算连续天数
```

示例：

```text
08-25 有记录
08-24 有记录
08-23 无记录
当前日期 08-26
连续打卡 2 天
```

### 4.6 状态结构建议

可以扩展运动目标相关 UI State：

```kotlin
data class ExerciseGoalProgressUiState(
    val weeklyGoalKm: Double,
    val monthlyGoalKm: Double,
    val weeklyDistanceKm: Double,
    val monthlyDistanceKm: Double,
    val weeklyRemainingKm: Double,
    val monthlyProgressPercent: Int,
    val weeklyCompleted: Boolean,
    val monthlyCompleted: Boolean,
    val streakDays: Int
)
```

具体命名可结合当前项目已有 `ExerciseUiState`、`ExerciseGoalUiState` 调整。

### 4.7 数据与刷新要求

目标增强数据应来自：

```text
ExerciseRecord Flow
ExerciseGoalRepository / DataStore Flow
```

数据变化后自动刷新：

```text
新增运动记录
编辑运动记录
删除运动记录
修改周/月目标
```

所有相关展示都应立即更新，不需要用户手动刷新页面。

### 4.8 UI 要求

继续沿用当前深色运动风：

```text
背景：#111820 / #151E26
强调色：#22C55E
主文字：接近白色
次级文字：灰色
```

展示要简洁，不要堆砌信息。

建议优先放在：

```text
ExerciseSummaryCard
ExerciseDetailScreen 顶部统计区域
```

不要新增复杂设置页。

### 4.9 验收标准

最终运动目标增强应满足：

- 能看到本周还差多少 km。
- 能看到月目标完成百分比。
- 周/月目标完成时有轻量提醒。
- 能看到连续打卡天数。
- 新增、编辑、删除运动记录后数据自动更新。
- 修改周/月目标后数据自动更新。
- 不影响现有运动记录弹窗、日期选择器、时长选择器。
- 不新增不必要的依赖。

## 5. 推荐实现顺序

建议分阶段执行：

```text
阶段一：体重趋势图独立模块
阶段二：趋势图区间筛选
阶段三：趋势图点选与目标体重线
阶段四：运动目标进度状态计算
阶段五：首页 / 详情页目标增强展示
阶段六：编译和回归验证
```

每个阶段完成后都需要编译验证。

## 6. 本提示词范围限制

后续根据本提示词实现时，不要顺带修改：

- APP 图标
- 打包脚本
- 首页体重卡片结构
- 运动记录录入弹窗
- 体重记录录入弹窗
- 已完成的返回按钮样式
- 已完成的顶部间距统一
- 数据库 Schema，除非确实需要且单独说明迁移方案

优先保持已有功能稳定，再逐步增强趋势图和目标体系。
