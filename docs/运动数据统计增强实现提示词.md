# 运动数据统计增强 实现提示词

请基于当前 Android 项目，继续增强运动详情页的数据统计能力。

本次需求只围绕：

```text
运动详情页统计维度增强
运动趋势图
个人最佳
连续打卡与月活跃天数
```

不要修改已经完成的 GPS 定位逻辑、轨迹绘制逻辑、轨迹保存逻辑、运动记录新增/编辑/删除、体重模块、首页卡片、地图样式切换等无关功能。

## 1. 当前背景

当前项目已有：

```text
ExerciseDetailScreen
ExerciseViewModel
ExerciseRecordEntity
ExerciseDao
Room + Flow
运动记录新增
运动记录编辑
运动记录删除
运动目标设置
周 / 月 / 年 / 全部 统计筛选基础能力
GPS 户外跑步记录
跑步机记录
运动详情页列表
```

当前运动详情页已经能展示部分统计信息，但统计维度还可以继续增强，趋势和个人最佳还未系统化展示。

## 2. 本次目标

运动详情页强化为更完整的数据看板，包含：

```text
1. 周 / 月 / 年 / 全部 筛选视图
2. 当前筛选范围内核心统计
3. 趋势图
4. 个人最佳
5. 连续打卡天数
6. 月活跃天数
```

目标是让运动详情页承担完整数据分析职责，首页继续保持简洁，不把过多统计信息堆到首页。

## 3. 统计维度

页面顶部继续保留或完善筛选控件：

```text
周 / 月 / 年 / 全部
```

每个维度切换后，相关统计和趋势图同步更新。

### 3.1 周

```text
当前自然周
周一 00:00:00 到当前时间
```

如果项目已有统一的周起始定义，必须复用，避免首页、详情页、目标进度统计口径不一致。

### 3.2 月

```text
当前自然月
本月 1 日 00:00:00 到当前时间
```

### 3.3 年

```text
当前自然年
1 月 1 日 00:00:00 到当前时间
```

### 3.4 全部

```text
全部运动记录
```

## 4. 核心统计字段

筛选范围内展示：

```text
累计里程
累计消耗
打卡天数
平均配速
单次最长距离
```

### 4.1 累计里程

计算：

```text
sum(distanceKm)
```

展示：

```text
xx.xx km
```

固定保留两位小数。

### 4.2 累计消耗

计算：

```text
sum(caloriesKcal)
```

展示：

```text
xxxx kcal
```

整数展示。

### 4.3 打卡天数

计算：

```text
筛选范围内不同自然日期数量
```

同一天多条运动记录只算 1 天。

展示：

```text
x 天
```

### 4.4 平均配速

计算：

```text
筛选范围内总运动时长 / 筛选范围内总里程
```

不要简单平均每条记录的配速。

无有效距离时展示：

```text
--'--"/km
```

### 4.5 单次最长距离

计算：

```text
max(distanceKm)
```

无记录时展示：

```text
0.00 km
```

有记录时固定两位小数。

## 5. 趋势图

在运动详情页增加趋势图模块，建议放在核心统计卡片下方、记录列表上方。

趋势图至少支持：

```text
周跑量
月跑量
平均配速变化
```

### 5.1 趋势图展示方式

建议使用页面内分段切换：

```text
[ 跑量 ] [ 配速 ]
```

第一版可以先实现两个图：

```text
跑量趋势图
平均配速趋势图
```

不要一次性加入过多图表类型，避免页面复杂。

### 5.2 跑量趋势

根据当前筛选维度决定聚合粒度：

```text
周：按天聚合，展示周一到周日每日里程
月：按天聚合，展示本月每日里程
年：按月聚合，展示 1 月到 12 月每月里程
全部：按月聚合，展示所有月份里程
```

展示格式：

```text
Y 轴：距离 km
X 轴：日期 / 月份
```

UI 要求：

```text
深色卡片背景
绿色折线或柱状图
网格线低透明度
空数据时显示轻量空状态
```

### 5.3 平均配速趋势

根据当前筛选维度聚合：

```text
周：按天计算每日平均配速
月：按天计算每日平均配速
年：按月计算每月平均配速
全部：按月计算每月平均配速
```

计算方式：

```text
聚合周期内总时长 / 聚合周期内总距离
```

无有效距离的周期不绘制点，或展示为空。

展示格式：

```text
x'xx"/km
```

注意：

```text
配速数值越小代表越快
图表 Y 轴需要处理“越低越好”的视觉关系
```

第一版可以只展示折线，不需要复杂交互。

## 6. 个人最佳

运动详情页增加个人最佳模块。

建议标题：

```text
个人最佳
```

第一版展示：

```text
最长距离
最快 1km
最快 5km
单次最高消耗
```

### 6.1 最长距离

计算：

```text
全部记录中 distanceKm 最大的单条记录
```

展示：

```text
xx.xx km
日期 yyyy-MM-dd
```

### 6.2 最快 1km

第一版建议计算口径：

```text
单次运动距离 >= 1km 的记录中
使用该条记录平均配速作为候选
取平均配速最快的一条
```

注意：

```text
如果当前数据库没有分段公里配速数据，不要伪造真实 1km 分段最佳。
```

展示文案建议：

```text
最快 1km
x'xx"/km
基于单次平均配速
```

后续如果引入轨迹分段计算，再升级为真实最快 1km。

### 6.3 最快 5km

第一版建议计算口径：

```text
单次运动距离 >= 5km 的记录中
使用该条记录平均配速作为候选
取平均配速最快的一条
```

展示文案建议：

```text
最快 5km
x'xx"/km
基于单次平均配速
```

如果无满足条件的记录，展示：

```text
--
```

### 6.4 单次最高消耗

计算：

```text
全部记录中 caloriesKcal 最大的单条记录
```

展示：

```text
xxxx kcal
日期 yyyy-MM-dd
```

## 7. 连续打卡天数

增加连续打卡天数统计。

计算规则：

```text
从今天开始向前连续检查是否存在运动记录
如果今天没有记录，则从昨天开始计算最近连续记录
同一天多条记录只算 1 天
中间断一天即停止
```

展示：

```text
连续打卡 x 天
```

建议同时展示最近一次打卡日期：

```text
最近打卡 yyyy-MM-dd
```

如果没有任何记录：

```text
连续打卡 0 天
```

## 8. 月活跃天数

增加当前自然月活跃天数。

计算：

```text
当前自然月内，有运动记录的不同日期数量
```

展示：

```text
本月活跃 x 天
```

同一天多条记录只算 1 天。

## 10. Compose 组件拆分建议

建议拆分：

```text
ExerciseStatsRangeSelector
ExerciseStatsOverviewCard
ExerciseTrendCard
ExerciseTrendChart
ExercisePersonalBestCard
ExerciseConsistencyCard
```

ViewModel 提供 UI State，Composable 只负责渲染。

建议数据结构：

```kotlin
data class ExerciseStatsUiState(
    val selectedRange: ExerciseStatRange,
    val overview: ExerciseStatsOverviewUiState,
    val trend: ExerciseTrendUiState,
    val personalBest: ExercisePersonalBestUiState,
    val consistency: ExerciseConsistencyUiState
)
```

趋势数据建议：

```kotlin
data class ExerciseTrendPointUiState(
    val label: String,
    val distanceKm: Double,
    val durationSeconds: Long,
    val averagePaceSecondsPerKm: Long?
)
```

个人最佳建议：

```kotlin
data class ExercisePersonalBestUiState(
    val longestDistance: PersonalBestItemUiState,
    val fastestOneKm: PersonalBestItemUiState,
    val fastestFiveKm: PersonalBestItemUiState,
    val highestCalories: PersonalBestItemUiState
)
```

## 11. 架构要求

数据计算放在 ViewModel 或独立统计计算类中。

不要在 Composable 中直接：

```text
遍历数据库实体计算统计
处理复杂日期逻辑
访问 Dao
访问 DataStore
```

建议新增纯 Kotlin 统计工具：

```text
ExerciseStatsCalculator
```

负责：

```text
筛选范围计算
统计聚合
趋势聚合
个人最佳计算
连续打卡计算
月活跃天数计算
```

这样便于后续写单元测试。

## 12. 空数据状态

如果没有运动记录：

```text
累计里程：0.00 km
累计消耗：0 kcal
打卡天数：0 天
平均配速：--'--"/km
单次最长距离：0.00 km
趋势图：暂无趋势数据
个人最佳：--
连续打卡：0 天
本月活跃：0 天
```

页面布局高度不要因为空数据大幅跳动。

## 13. 测试建议

至少覆盖以下场景：

```text
无运动记录
同一天多条记录
跨周记录
跨月记录
跨年记录
只有跑步机记录
只有户外跑步记录
跑步机 + 户外跑步混合记录
距离为 0 或异常数据
不足 1km 时最快 1km 为空
不足 5km 时最快 5km 为空
连续打卡中断
今天未打卡但昨天及之前连续打卡
```

如果项目已有单元测试框架，优先给 `ExerciseStatsCalculator` 增加测试。
