# MyRunApp 需求文档

## 1. 文档目的

本文整理 MyRunApp 当前产品需求，覆盖已确认的 V1.0 体重记录能力，以及 V1.1 运动记录、首页双卡片、体重曲线扩展、屏幕适配和 App 图标要求。

## 2. 版本范围

### 2.1 V1.0 范围

V1.0 是单机离线体重记录工具，只解决两个核心问题：

1. 快速记录每天体重。
2. 通过曲线查看体重变化。

V1.0 不包含运动、目标体重、时间筛选、历史列表、账号、云同步、社区、广告、健康平台接入等能力。

### 2.2 V1.1 范围

V1.1 在 V1.0 基础上扩展为轻量个人运动与体重记录工具。

V1.1 新增：

- 首页展示运动记录卡片和体重卡片。
- 每日运动记录：距离、时长、消耗热量。
- 运动统计：日、周、月、年、全部累计。
- 体重详细页和运动详细页。
- 体重曲线按时间区间查看。
- 体重曲线支持横屏和竖屏展示。
- App 使用自定义运动健康风格图标。
- 以荣耀 Magic8 为当前主适配设备，同时保留后续设备适配能力。

V1.1 仍保持：

- 离线可用。
- 无账号。
- 无云同步。
- 无广告。
- 不接入 GPS 自动轨迹、智能设备或 Health Connect。

## 3. 用户与场景

目标用户是希望手动记录体重和运动数据的个人用户。

核心场景：

- 每天称重后记录体重。
- 每天运动后记录运动距离、时长和热量。
- 打开首页快速查看运动和体重两个核心入口。
- 进入运动详情查看周期累计。
- 进入体重详情查看体重曲线和记录情况。
- 无网络环境下继续记录和查看数据。

## 4. 信息架构

V1.1 建议包含三个主页面：

- 首页。
- 运动详情页。
- 体重详情页。

首页只展示摘要和入口，不承载完整记录列表。

```text
首页
├── 运动记录卡片 -> 运动详情页
└── 体重卡片     -> 体重详情页
```

## 5. 首页需求

### 5.1 首页结构

首页展示两个核心卡片：

- 运动记录卡片。
- 体重卡片。

首页不再堆叠散乱指标，核心信息收敛到两个卡片中。

### 5.2 运动记录卡片

运动记录卡片展示：

- 历史记录。
- 进入记录。

展示规则：

- 有运动记录时，历史记录区域展示运动摘要，例如最近一次运动、累计距离、累计时长或累计热量。
- 具体摘要字段可在 UI 设计阶段确认，但必须来自运动记录数据。
- 无运动记录时，运动数据展示 `-`。
- “进入记录”始终展示并可点击。

点击行为：

- 点击运动记录卡片主体区域，进入运动详情页。
- 点击“进入记录”，同样进入运动详情页。
- 无记录状态也允许进入运动详情页，详情页展示空状态和新增记录入口。

### 5.3 体重卡片

体重卡片展示：

- 目标体重。
- 今天的体重。
- 打卡次数。

展示规则：

- 有目标体重时展示目标体重；无目标体重时展示 `-`。
- 当天有体重记录时展示今天的体重；当天无体重记录时展示 `-`。
- 打卡次数按有体重记录的自然日数量计算。
- 无任何体重记录时，今天的体重和打卡次数展示 `-`。

点击行为：

- 点击体重卡片主体区域，进入体重详情页。
- 体重详情页包含体重曲线、体重记录入口和目标体重相关展示或设置入口。

### 5.4 首页示例

```text
首页

[运动记录]
历史记录：-
进入记录 >

[体重]
目标体重：-
今天体重：-
打卡次数：-
```

## 6. 体重记录需求

### 6.1 新增体重

用户可以录入：

- 日期。
- 体重。

默认行为：

- 日期默认当天。
- 体重单位固定为 kg。
- 体重支持一位小数。

示例：

```text
日期：2026-08-20
体重：77.2 kg
```

### 6.2 输入规则

日期：

- 格式为 `yyyy-MM-dd`。
- 默认使用设备本地日期。
- 不记录具体时间。

体重：

- 单位固定为 kg。
- 保存和展示均保留一位小数。
- 合理范围为 `30.0 kg ～ 300.0 kg`。

校验规则：

- 空值、非数字、负数不允许保存。
- 小于 30.0 kg 或大于 300.0 kg 不允许保存。
- 超过一位小数时提示用户修正，不静默截断。

错误提示建议：

```text
请输入 30.0～300.0 kg 之间的体重
```

### 6.3 同一天重复记录

一天只保留一条体重记录。

如果选择日期已有记录，再次保存时覆盖当天记录。

保存成功后：

- 弹窗关闭。
- 首页体重卡片自动刷新。
- 体重详情页曲线自动刷新。
- 可通过轻提示显示“已保存”。

## 7. 体重详情页需求

体重详情页展示：

- 最新体重。
- 最新记录日期。
- 目标体重。
- 体重曲线。
- 时间区间切换。
- 记录体重入口。

无记录状态：

- 最新体重展示 `-- kg` 或 `-`。
- 最新记录日期展示“暂无记录”或 `-`。
- 曲线区域展示空状态。
- 记录体重入口仍可点击。

## 8. 体重曲线需求

### 8.1 基础规则

曲线按记录日期升序绘制。

横轴：

- 日期。
- 记录较多时只显示部分日期标签，避免拥挤。

纵轴：

- 体重 kg。
- 根据当前可见数据范围自动调整。

折线：

- 显示数据点。
- 显示点之间连线。
- 当前区间内最后一个数据点可适当突出。

### 8.2 时间区间

体重曲线支持按时间区间查看。

支持区间：

- 7 天。
- 30 天。
- 90 天。
- 1 年。
- 全部。

默认区间：

- 默认展示 `30 天`。
- 总记录不足 30 天时展示已有记录。
- 用户切换区间后，本次页面生命周期内保持当前选择。

区间定义：

- 7 天：从当前设备日期向前包含最近 7 个自然日。
- 30 天：从当前设备日期向前包含最近 30 个自然日。
- 90 天：从当前设备日期向前包含最近 90 个自然日。
- 1 年：从当前设备日期向前包含最近 365 个自然日。
- 全部：所有体重记录。

切换规则：

- 切换区间只影响曲线数据。
- 首页体重卡片不受曲线区间影响。
- 运动统计区间不受体重曲线区间影响。
- 切换区间后，Y 轴范围按当前区间数据重新计算。

### 8.3 Y 轴范围

Y 轴不固定为 `0～100kg`。

建议规则：

- 取当前区间内最小体重和最大体重。
- 上下至少预留 `1.0kg`。
- 最小跨度不少于 `2.0kg`。
- 可按 `0.5kg` 或 `1.0kg` 对齐，提高可读性。

### 8.4 边界状态

无记录：

- 显示空状态，不绘制折线。

当前区间无记录：

- 曲线区域显示空状态。

只有一条记录：

- 显示一个数据点。
- Y 轴围绕该体重上下留出空间。

多条同体重记录：

- 显示水平折线。
- Y 轴仍保留最小视觉跨度。

### 8.5 横竖屏展示

竖屏是默认和主要使用形态。

竖屏要求：

- 曲线不占满整屏。
- 曲线与核心体重、区间切换控件、主要入口保持合理比例。
- 图表清晰，留白克制，坐标不拥挤。
- 区间切换控件与曲线强关联，不能离图表过远。

横屏要求：

- 曲线获得更宽展示空间。
- 可增加 X 轴日期标签数量，但仍需避免拥挤。
- 核心体重、区间切换控件和曲线可以左右或上下重排。
- 图表不能被系统状态栏、导航栏或底部操作遮挡。

切换要求：

- 横竖屏切换后，当前体重曲线区间保持不变。
- 曲线数据、最新体重和运动统计不丢失。
- 不触发重复保存或重置录入状态。
- 竖屏和横屏都要处理空数据、单条数据和多条数据。

## 9. 运动记录需求

### 9.1 新增运动记录

用户可以录入：

- 日期。
- 运动距离。
- 运动时长。
- 消耗热量。

默认行为：

- 日期默认当天。
- 距离单位固定为 km。
- 时长单位固定为分钟。
- 热量单位固定为 kcal。

示例：

```text
日期：2026-08-20
距离：5.2 km
时长：32 分钟
热量：310 kcal
```

### 9.2 输入规则

日期：

- 格式为 `yyyy-MM-dd`。
- 默认使用设备本地日期。
- V1.1 暂不记录具体开始时间和结束时间。

距离：

- 单位固定为 km。
- 支持一位或两位小数。
- 合理范围建议为 `0.1 km ～ 200.0 km`。

时长：

- 单位固定为分钟。
- 输入正整数。
- 合理范围建议为 `1 分钟 ～ 1440 分钟`。

热量：

- 单位固定为 kcal。
- 输入正整数。
- 合理范围建议为 `1 kcal ～ 10000 kcal`。

### 9.3 同一天多次运动

运动记录支持同一天多条。

原因：

- 用户可能一天内多次跑步、骑行或健走。
- 日累计统计可以自然汇总。
- 运动记录不受“每天只有一条”的体重业务约束。

## 10. 运动详情页需求

运动详情页展示：

- 周期切换。
- 当前周期累计距离。
- 当前周期累计时长。
- 当前周期累计消耗热量。
- 运动记录列表。
- 新增运动记录入口。

统计维度：

- 日累计。
- 周累计。
- 月累计。
- 年累计。
- 全部累计。

周期定义：

- 日：所选自然日。
- 周：ISO 周，周一到周日。
- 月：自然月。
- 年：自然年。
- 全部：所有运动记录。

示例：

```text
本周累计
距离：28.4 km
时长：3小时06分钟
热量：1,720 kcal
```

无记录状态：

- 核心运动数据展示 `-`。
- 列表展示空状态。
- 新增运动记录入口仍可点击。

## 11. 视觉与品牌要求

### 11.1 整体视觉

整体视觉参考运动数据类 App 的设计气质，但不复制任何第三方品牌素材。

设计方向：

- 深色或高对比运动风格。
- 大数字突出核心数据。
- 卡片承载首页入口和关键摘要。
- 单一高亮色强调关键数据和主要操作。
- 页面保持简洁，不加入社区、资讯、广告等干扰信息。

限制：

- 不使用悦跑圈 Logo、品牌图标、截图或专有素材。
- 不直接复制悦跑圈页面布局和文案。
- 不加入社区动态、排行榜、训练计划、广告等功能。

### 11.2 首页卡片视觉

两个首页卡片应保持统一设计语言：

- 卡片标题清晰。
- 核心数字突出。
- 无记录时使用 `-`，不要显示 0 造成误解。
- 卡片整体可点击，并有明确点击反馈。
- 卡片之间间距一致。
- 大字体模式下内容可换行或自然增高，不允许重叠。

### 11.3 App 图标

App 不能使用 Android 原生默认图标，需要使用自定义图标。

图标定位：

- 年轻。
- 健康。
- 有运动感。
- 能体现运动记录和体重管理主题。

视觉方向：

- 主色建议使用绿色、青色、亮蓝或荧光黄绿色。
- 图形可以结合跑步轨迹、上升或变化曲线、运动鞋轮廓、速度线、心率线、体重刻度等元素。
- 小尺寸下仍可识别。
- 不依赖细碎文字。
- 与 App 内深色运动风界面保持一致。

限制：

- 不使用 Android 默认机器人图标。
- 不使用第三方 App 的 Logo、图标、截图或品牌素材。
- 不复刻悦跑圈或其他运动 App 图标。

## 12. 屏幕适配

当前首要适配设备：

- 荣耀 Magic8（用户原始描述为“荣耀 MIGIC8”）。

适配目标：

- V1.1 页面视觉和交互优先在该设备上完成实机验证。
- 首页、运动详情页、体重详情页不得出现文字重叠、按钮遮挡、系统手势区遮挡等问题。
- 核心数据大数字、周期切换控件、列表项、记录按钮在该设备上应具备良好可读性和可点击性。

后续设备适配要求：

- UI 控件尺寸不按某一台设备的物理像素写死。
- 控件高度、间距、字号、图表高度、底部安全区域等使用可复用尺寸定义。
- 页面布局使用响应式约束，适配不同屏幕高度、宽度和字体缩放。
- 窄屏、小屏、高屏和大字体模式下，核心内容仍能完整展示或自然滚动。
- 后续更换设备时优先调整全局尺寸定义，避免逐页改 UI。

## 13. 不开发范围

V1.1 暂不开发：

- 登录注册。
- 后台服务器。
- 云同步。
- 好友和社区。
- 排行榜。
- 广告。
- GPS 轨迹记录。
- 自动配速计算。
- 运动类型细分。
- 跑步路线地图。
- 运动分享海报。
- 训练计划。
- 饮食记录。
- AI 分析。
- 智能手表、体脂秤等设备接入。
- Health Connect 或第三方健康平台同步。

## 14. 验收标准

### 14.1 首页验收

- 首页同时展示运动记录卡片和体重卡片。
- 运动无记录时，运动卡片数据展示 `-`。
- 体重无记录时，目标体重、今天体重、打卡次数展示 `-`。
- 点击运动记录卡片进入运动详情页。
- 点击运动卡片内“进入记录”进入运动详情页。
- 点击体重卡片进入体重详情页。
- 荣耀 Magic8 竖屏下两个卡片布局完整、内容不重叠。

### 14.2 体重验收

- 可以新增体重记录。
- 日期默认当天。
- 体重支持一位小数。
- 非法体重不能保存。
- 同一天重复保存会覆盖当天记录。
- 保存成功后首页体重卡片和体重详情页自动刷新。
- 体重曲线按日期升序展示。
- 体重曲线支持 7 天、30 天、90 天、1 年、全部区间。
- 区间无记录时显示空状态。
- 区间切换不影响首页体重卡片。
- 横竖屏切换后，选中的时间区间保持一致。
- 横竖屏切换后，图表 Y 轴仍按当前区间数据正确计算。

### 14.3 运动验收

- 可以新增运动记录。
- 运动记录包含日期、距离、时长、消耗热量。
- 同一天可保存多条运动记录。
- 运动详情页可查看日、周、月、年、全部累计数据。
- 累计距离、时长、热量计算准确。
- 无运动记录时，首页和运动详情页有合理空状态。

### 14.4 视觉与适配验收

- App 使用自定义运动健康风格图标，不使用 Android 默认图标。
- 页面视觉具备运动数据类 App 气质，但不复刻第三方品牌资产。
- 荣耀 Magic8 竖屏下，首页和详情页核心内容清晰可见。
- 荣耀 Magic8 横屏下，体重曲线有更宽展示空间，日期标签不重叠。
- 系统字体调大后，核心数据不截断，非核心信息可换行或滚动。
- 关闭网络后仍可正常记录和查看体重、运动数据。

### 14.5 打包交付验收

- 提供 Debug 打包脚本。
- 提供 Release 打包脚本。
- Debug 脚本生成可用于本地安装测试的 Debug 包。
- Release 脚本生成用于正式验收或分发的 Release 包。
- Release 打包不提交明文签名密码或 keystore 等敏感信息。
