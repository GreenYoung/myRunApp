# BUG 修改汇总

本文档用于持续记录 MyRunApp 开发过程中用户反馈的 BUG、原因分析、修改方案、处理状态和后续验证点。

## 1. 开始运动页地图定位不准确

### 问题描述

- 进入开始运动页面后，地图显示位置与真实位置存在明显偏差。
- 用户实际在武汉，但地图曾出现定位到深圳的问题。
- 地图缩放到道路级后，定位误差被进一步放大，看起来像“不在当前位置”。

### 初步原因

- 早期代码中无定位结果时使用了固定默认坐标，默认点曾为深圳。
- 高德定位成功后只判断 `errorCode == SUCCESS`，没有判断定位精度和定位来源。
- 网络定位、缓存定位、粗定位也可能被直接用于地图展示。
- 跑步页当前位置来自高德定位，运动轨迹记录来自系统 GPS，两套定位源可能短时间内不一致。

### 已执行方案

- 去掉深圳默认坐标，默认中心改为武汉兜底坐标。
- 高德定位从一次性定位改为页面内持续定位。
- 新增 `RunMapLocation`，保存当前位置、精度和道路级可靠性。
- 增加定位质量过滤：
  - 高德返回失败不使用。
  - 坐标不可用于地图不使用。
  - 上次缓存定位不使用。
  - 精度大于 `50m` 不用于当前位置展示。
  - 精度 `<= 30m` 才允许道路级缩放。
- 增加定位调试日志，输出 `accuracy / locationType / gpsAccuracyStatus / coordType / isOffset / isCoorCanUseInMap`。

### 后续验证点

- 真机进入开始运动页后，观察是否能自动定位到当前位置附近。
- 查看 `RunMapLocation` 日志，确认实际定位类型是否为高质量定位。
- 如果仍然偏移，需要判断是定位精度问题、坐标系问题，还是需要轨迹纠偏服务。

## 2. 开始运动页没有显示当前位置

### 问题描述

- 进入跑步页面后，地图上没有明显的“自己当前位置”标记。
- 未点击开始运动时，地图只有底图，没有当前位置点。

### 原因分析

- `AMapRunTrackingMap` 只把高德定位结果用于移动地图视角，没有绘制当前位置 marker。
- `drawSportTrack()` 在轨迹点为空时直接返回，导致无轨迹点时不会绘制任何位置标记。

### 已执行方案

- 新增当前位置 marker 绘制：
  - 绿色实心圆点。
  - 半透明绿色外圈。
  - 白色细描边提升可见性。
- 当轨迹点为空时，也会绘制当前位置 marker。
- 当前位置 marker 支持与轨迹、GO、END、公里标记叠加显示。

### 后续验证点

- 未开始运动时，地图上应能看到当前位置圆点。
- 已开始运动但轨迹点还不足时，仍应能看到当前位置。

## 3. 实时轨迹显示不明显或刚开始没有轨迹

### 问题描述

- 点击开始运动后，地图上没有立即看到实时轨迹。
- 刚开始运动时可能只有当前位置，没有轨迹线。

### 原因分析

- 真实轨迹点来自 `RunTrackingService`。
- GPS 过滤器有预热和异常点过滤逻辑，前几个定位点可能不会立即进入轨迹列表。
- 轨迹点少于 2 个时无法绘制轨迹线。

### 已执行方案

- 轨迹绘制规则调整：
  - 无轨迹点：显示当前位置 marker。
  - 1 个轨迹点：显示起点和当前位置。
  - 2 个及以上轨迹点：绘制轨迹线、起点、终点/当前位置和公里标记。
- 地图跟随策略调整：
  - 轨迹点少于 2 个时，优先跟随高德当前位置。
  - 轨迹点达到 2 个后，跟随最新真实轨迹点。

### 后续验证点

- 开始运动后，前几秒应至少能看到当前位置。
- 有效轨迹点达到 2 个后，应开始绘制轨迹线。

## 4. 轨迹相对高德地图道路偏移

### 问题描述

- 实际在道路上运动，但轨迹显示到附近其他道路或偏离道路。

### 原因分析

- Android 系统 GPS 原始坐标通常为 `WGS84`。
- 高德地图底图使用 `GCJ-02`。
- 如果直接把系统 GPS 坐标画到高德地图上，会产生坐标系偏移。

### 已执行方案

- 新增 `MapCoordinateTransform.kt`。
- 系统 GPS 轨迹点在地图展示前统一执行 `WGS84 -> GCJ-02`。
- 高德定位点不重复转换，因为高德定位配置 `setOffset(true)` 后返回的是高德地图可用坐标。

### 后续验证点

- 历史轨迹和实时轨迹应比之前更贴近道路。
- 如果仍有道路吸附级别的偏差，需要评估高德猎鹰轨迹纠偏。

## 5. 跑步页地图没有放大到道路级

### 问题描述

- 进入跑步页后地图比例偏小，只显示城市或区县级别。

### 原因分析

- 早期无轨迹点时默认 zoom 较低。
- 高德定位不可靠时直接放大到道路级，会导致偏差更明显。

### 已执行方案

- 增加道路级缩放策略：
  - 定位精度 `<= 30m`：缩放到道路级 `zoom = 18`。
  - 定位精度 `30m ~ 50m`：只缩放到较保守级别，避免误差被放大。
  - 无可靠定位时使用武汉默认坐标兜底。

### 后续验证点

- 定位稳定时应自动进入道路级视图。
- 定位较差时不应盲目放大导致用户误判。

## 6. 跑步轨迹样式不符合运动 App 预期

### 问题描述

- 轨迹样式较普通，没有明显运动 App 氛围。
- 起点、终点、公里节点不够直观。

### 已执行方案

- 轨迹线改为渐变色。
- 起点使用 `GO` 标记。
- 终点使用 `END` 标记。
- 跑步中当前位置可显示 `LIVE`。
- 每满 1km 在轨迹上增加公里数字 marker。

### 后续验证点

- 历史轨迹详情页和实时跑步页应保持一致的轨迹视觉。
- 如果 marker 遮挡严重，再调整 marker 尺寸和层级。

## 7. 运动详情下拉列表户外跑步条目排版不合理

### 问题描述

- 运动详情下拉列表中，户外跑步条目的“户外”文字没有和跑步机条目的“跑步机”文字 start 对齐。
- 户外跑步条目左侧增加轨迹缩略图后，文字区域整体右移，导致列表视觉不统一。
- 距离、时长、配速、消耗四个指标挤在同一行时信息密度偏高，户外跑步条目看起来不够清晰。

### 原因分析

- 跑步机条目使用 `BasicExerciseRecordItem`，顶部是图标 + 类型 + 日期的权重布局。
- 户外跑步条目使用 `OutdoorExerciseRecordItem`，左侧额外展示 `TrackThumbnail`，右侧内容区域单独布局。
- 两个 item 没有共享同一套“类型文字起始位置”和“日期位置”对齐规则。
- 户外跑步指标仍沿用一行四列展示，在带缩略图的场景下横向空间更紧张。

### 修改方案

- 保留户外跑步左侧轨迹缩略图，但重新定义户外条目的内部布局。
- 让“户外”文字与跑步机模式中的“跑步机”文字 start 对齐：
  - 方案一：户外条目顶部仍保留缩略图，但右侧文字列内部增加固定起始偏移，与基础条目文字列对齐。
  - 方案二：统一抽取列表标题行组件，明确类型文字起始基准线，户外缩略图作为独立视觉元素，不影响标题文字基准。
- 户外跑步指标改为两行展示：
  - 第一行：距离、时长。
  - 第二行：配速、消耗。
- 两行指标使用固定权重列，保证 start 对齐、间距一致。
- 分割线样式继续复用当前运动列表分割线，不引入新的视觉样式。

### 验收标准

- “户外”和“跑步机”文字左侧起点视觉一致。
- 户外跑步条目中指标展示为两行。
- 距离/时长、配速/消耗两组信息对齐清晰。
- 不影响跑步机条目的现有展示。
- 不影响点击进入详情和长按删除等已有交互。

## 8. 运动详情下拉列表日期格式不完整

### 问题描述

- 运动详情下拉列表日期当前展示为 `08-26`。
- 用户要求展示完整年份，例如 `2026-08-26`。
- 详情页面日期展示正常，只是下拉列表展示格式不完整。

### 原因分析

- 当前 `formatExerciseDateTime(startTime)` 使用 `MM-dd` 格式。
- 运动列表 UI 使用的是 `ExerciseRecordUiModel.dateTimeText`，该字段由 `formatExerciseDateTime()` 生成。
- 因此列表日期天然缺少年份。

### 修改方案

- 将运动列表日期格式从 `MM-dd` 调整为 `yyyy-MM-dd`。
- 优先新增或修改列表专用格式化函数，避免影响输入弹窗或详情页已有日期格式。
- 调整列表日期所在列宽，确保 `2026-08-26` 不被截断。
- 日期仍保持右侧对齐或与当前 calories 起点规则一致，避免破坏列表整体对齐。

### 验收标准

- 运动详情下拉列表日期展示为 `yyyy-MM-dd`。
- 日期不截断、不换行。
- 跑步机和户外跑步两类记录日期展示一致。
- 不影响运动记录详情页当前日期展示。

## 当前建议

下一次真机测试时，重点采集以下信息：

```text
RunMapLocation 日志：
accuracy
locationType
gpsAccuracyStatus
coordType
isOffset
isCoorCanUseInMap
isFixLastLocation
```

如果日志显示精度稳定在 `10m ~ 30m` 但轨迹仍明显偏离道路，说明单纯坐标转换和定位过滤已经接近上限，后续应进入“猎鹰轨迹纠偏 / 道路吸附 / 轨迹平滑”的优化阶段。
