## 2. 改动二：统计详情页 pill 文案修复（方案 C）

### 2.1 现状与根因

```kotlin
// ExerciseStatsDetailScreen.kt:231-264
@Composable
private fun ExerciseStatsPeriodPill(period: ExerciseStatsPeriod, periodOffset: Int) {
    val text = if (periodOffset == 0) {
        when (period) { WEEK -> "本周"; MONTH -> "本月"; YEAR -> "今年" }
    } else {
        when (period) {                 // ← BUG 所在
            WEEK -> "周"; MONTH -> "月"; YEAR -> "年"
        }
    }
    ...
}
```

1. **直接原因**：`else` 分支只写回周期单位，漏了「哪一期」——本周翻到上一周就退化成量词「周」。
2. **结构性原因**：标签在 Composable 里现算、只有 `offset == 0 / != 0` 两态，无法表达「上周 / 3周前」，也无法单测；与 `docs/REPO_MAP.md:24`「统计计算在 `ExerciseStats.kt`，Composable 只负责渲染」的分层相反。
3. **年统计**：同一段代码 `YEAR -> "年"`，翻到去年同样只剩「年」（详见 §3）。

影响面：`periodOffset != 0` 即触发；周/月/年共用同一 pill，一处修复全部生效；全工程 `periodOffset` 只出现在 `ExerciseModels.kt` / `ExerciseStats.kt` / `ExerciseStatsDetailScreen.kt` / `ExerciseViewModel.observeStatsDetail`。

### 2.2 文案规则（已确认）

| 周期 | offset = 0 | offset = -1 | offset ≤ -2 |
| --- | --- | --- | --- |
| 周 | `本周` | `上周 · 11.09-11.15` | `3周前 · 10.26-11.01` |
| 月 | `本月` | `上月 · 2026.10` | `3个月前 · 2026.08` |
| 年 | `今年` | `去年 · 2025` | `3年前 · 2023` |

设计约束：

- **本期不带区间**（已确认）：当期区间被 `coerceAtMost(nowMillis)` 截到今天（`ExerciseStats.kt:237`），周一当天会变成 `本周 · 11.16-11.16` 这种单日区间，看起来像 bug；「本周」语义已完整，区间由卡片下方 subline 给出。
- 周用 `MM.dd` 两端、月用 `yyyy.M`、年用 `yyyy`，分隔符统一 `" · "`（紧凑优先，与 subline 的中文长格式分工：pill 求短、subline 求可读）。
- 跨年周（`12.29-01.04`）不额外补年份，年份由 subline 的 `rangeText` 兜底。
- **宽度预算**：360dp 屏下 pill 可用 228dp（内容 292dp − 箭头区 64dp）；最长文案 `3个月前 · 2026.08` ≈ 118dp，1.3 倍字号 ≈ 153dp，仍有富余。真机若截断，兜底顺序：①两行 pill（上行相对词 11sp、下行区间 9sp）②只留相对词。

#### ② `ExerciseStats.kt`：新增标签函数并写入 UiState

```kotlin
internal fun statsPeriodLabel(
    period: ExerciseStatsPeriod,
    offset: Int,
    rangeStartMillis: Long,
    rangeEndMillis: Long
): String = when (period) {
    ExerciseStatsPeriod.WEEK -> when (offset) {
        0 -> "本周"
        else -> "${weekRelativeLabel(offset)} · " +
            AppDateFormats.format("MM.dd", rangeStartMillis) + "-" +
            AppDateFormats.format("MM.dd", rangeEndMillis)
    }
    ExerciseStatsPeriod.MONTH -> when (offset) {
        0 -> "本月"
        else -> "${monthRelativeLabel(offset)} · " + AppDateFormats.format("yyyy.M", rangeStartMillis)
    }
    ExerciseStatsPeriod.YEAR -> when (offset) {
        0 -> "今年"
        else -> "${yearRelativeLabel(offset)} · " + AppDateFormats.format("yyyy", rangeStartMillis)
    }
}

private fun weekRelativeLabel(offset: Int) = if (offset == -1) "上周" else "${-offset}周前"
private fun monthRelativeLabel(offset: Int) = if (offset == -1) "上月" else "${-offset}个月前"
private fun yearRelativeLabel(offset: Int) = if (offset == -1) "去年" else "${-offset}年前"
```

`buildExerciseStatsDetail()` 返回值（`:251-267`）加一行：

```kotlin
periodLabel = statsPeriodLabel(period, safeOffset, startMillis, endMillis),
```

两个要点：

- 用 **`safeOffset`**（已 clamp 到 `[minOffset, 0]`），否则标签可能与数据错位一期。
- `endMillis` 已包含 `coerceAtMost(nowMillis)`，非本期时等于该周周日 23:59:59.999，格式化日期正确。

## 4. 改动三（A1）：周/月/年区间文案改短且本地化

### 4.1 现状

`buildStatsRangeText()`（`ExerciseStats.kt:471-473`）固定输出 ISO 日期：

```
2026-11-16 至 2026-11-17        （本周）
2026-10-01 至 2026-10-31        （上月）
2025-01-01 至 2025-12-31        （去年）
```

技术上无错，但和 App 其它地方（`M月d日`、`M月d日 至 M月d日`）风格不一致，年视图尤其冗余。

### 4.2 目标文案

| 周期 | 场景 | 新文案 |
| --- | --- | --- |
| 周 | 本期，起止同一天（周一当天） | `11月16日` |
| 周 | 本期，普通情况（今天 11-17 周二） | `11月16日 - 11月17日` |
| 周 | 往年同一周 | `2025年10月20日 - 10月26日` |
| 周 | 跨年周 | `2025年12月29日 - 2026年1月4日` |
| 月 | 本年 | `10月1日 - 10月31日` |
| 月 | 往年 | `2025年10月1日 - 10月31日` |
| 年 | 往年（完整年） | `2025年` |
| 年 | 当年 | `2026年（至 11月17日）` |

规则：`M月d日`（不补零）；**起止同一天只写一天**；**跨年时两端都带年份**；**同一年但非当年时在起始端带一次年份**；年视图整年只写 `yyyy年`。

### 4.3 实现

签名加 `period` / `isCurrentPeriod` / `nowMillis`（后者为可测性）：

```kotlin
internal fun buildStatsRangeText(
    period: ExerciseStatsPeriod,
    startMillis: Long,
    endMillis: Long,
    isCurrentPeriod: Boolean,
    nowMillis: Long = System.currentTimeMillis()
): String
```

`buildExerciseStatsDetail()` 调用处（`:255`）改为：

```kotlin
rangeText = buildStatsRangeText(period, startMillis, endMillis, isCurrentPeriod = safeOffset == 0),
```

要点：

- 用 `Calendar` 取年/月/日（与文件内既有 `startOf*` 系列一致），不新引 `java.time`。
- 同一天判定用 `dateKey()`（文件内已有 `yyyy-MM-dd`），避免时分秒干扰。
- 当年判定用 `nowMillis` 推 `Calendar`，测试可传固定时间，避免跨年时用例失效。

### 4.4 影响面与风险

- `rangeText` 全工程只有一处消费：`ExerciseStatsDetailScreen.kt:220` 的 `累计里程 · ${uiState.rangeText}`。
- 默认参数保证旧调用点不用改；无数据库/序列化影响。
- 风险：低。唯一语义变化是「文字更短」，不影响任何统计数值。

## 5. 改动四（A2）：空周期显示「该周期暂无运动记录」

### 5.1 现状

翻到没有记录的一期时，卡片显示 `0.00 km`、`累计里程 · 区间`、下方 8 个指标全 0。数值是对的，但用户容易以为数据没加载出来（尤其刚翻页的瞬间）。

### 5.2 方案

`ExerciseStatsHero` 大数字下方的 subline（`ExerciseStatsDetailScreen.kt:209-225`）按是否有记录分支：

```kotlin
val hasRecords = uiState.recordCount > 0
Row(...) {
    Box(dot)                                  // 绿点保持不动
    Text(
        text = if (hasRecords) "累计里程 · ${uiState.rangeText}" else "该周期暂无运动记录",
        color = AppSecondaryText,
        fontSize = 12.sp,
        maxLines = 1
    )
}
```

四个决定：

1. **大数字保留 `0.00 km`**，不改 `--.--`：与下方「0 次 / 0 天 / 00:00:00」保持一致的"真实的零"，避免出现"没有数据"和"未加载"两种语义混淆。
2. **不丢区间信息**：非本期时 pill 已带区间（方案 C），所以 subline 用纯提示不会丢失上下文；本期无区间时用户本来就知道是本周。
3. **不新增 UiState 字段**：直接用现成的 `uiState.recordCount == 0`（`ExerciseStats.kt:259` 已提供）。
4. **不额外加图标/空状态插画**：保持这一屏的数据密度，只换一行文案。

### 5.3 风险

低。纯展示分支，不改统计逻辑。唯一注意点：`recordCount` 与 `totalDistanceKm` 理论上可能不一致（有记录但距离为 0），此时会显示「该周期暂无运动记录」但下方「运动次数 1 次」——可接受；若在意，可把条件改成 `recordCount == 0 && totalDistanceKm == 0.0`。
