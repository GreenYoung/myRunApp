# 高德实时跑步地图页实现提示词

请基于当前 Android 项目，实现「RunTrackingScreen 高德实时跑步地图页」改造。

本次目标是将当前跑步记录页从深色信息面板布局，改为类似运动类 APP 的地图主视图：地图铺满全屏，跑步数据作为悬浮卡片显示在地图上层底部，跑步轨迹实时绘制在地图上。

## 1. 当前背景

项目当前已经实现：

- `RunTrackingScreen`：户外跑步记录页。
- `RunTrackingViewModel`：提供实时跑步状态。
- `RunTrackingUiState`：包含实时距离、时长、配速、GPS 状态、轨迹点等。
- `RunTrackingService`：前台服务记录 GPS，支持息屏继续记录。
- `RunTrackingStateStore`：维护服务状态流。
- `RunTrackPointUiModel`：轨迹点 UI 模型。
- `RunTrackDetailScreen`：跑步结束后轨迹详情页。
- `AMapTrackPreview`：已实现高德地图轨迹预览，用于结束后的轨迹详情页。
- 高德轻量地图合包 AAR 已接入：

```text
app/libs/amap-lite3d-search-location.aar
```

当前 `RunTrackingScreen` 布局大致为：

```text
深色背景
顶部返回 + 标题
距离
时长 / 配速
GPS 状态
底部按钮
```

本次要改为：

```text
高德地图全屏背景
顶部返回按钮悬浮在地图上
底部跑步信息卡片悬浮在地图上
轨迹实时绘制在地图上
```

## 2. 本次目标

最终视觉结构：

```text
┌──────────────────────────────┐
│ ◯‹                           │
│                              │
│                              │
│          高德地图             │
│       实时绿色轨迹线           │
│                              │
│                              │
│ ┌──────────────────────────┐ │
│ │        3.26 km            │ │
│ │        当前距离            │ │
│ │                          │ │
│ │  21:36       6'37"/km     │ │
│ │  运动时长     平均配速      │ │
│ │                          │ │
│ │ GPS 信号良好 · 息屏记录中   │ │
│ │                          │ │
│ │      [ 结束跑步 ]          │ │
│ └──────────────────────────┘ │
│                              │
└──────────────────────────────┘
```

要求：

- 地图铺满整个屏幕。
- 跑步信息卡片显示在地图上层。
- 卡片位于屏幕底部。
- 卡片距离屏幕底部保留一定间距，避免贴住导航栏。
- 实时轨迹点在地图上绘制成绿色 Polyline。
- 跑步过程中地图跟随最新轨迹点。
- 没有轨迹点时地图仍然显示，不要显示空白大块。

本次只修改：

- `RunTrackingScreen`
- 与实时地图展示相关的 Compose 组件

RunTrackingMapView

app/src/main/java/com/example/myrunapp/feature/run/AMapRunTrackingMap.kt

## 4. 地图层设计

`RunTrackingScreen` 根布局建议使用 `Box`：

```kotlin
Box(modifier = Modifier.fillMaxSize()) {
    AMapRunTrackingMap(...)
    TopBackButton(...)
    RunTrackingOverlayCard(...)
}
```

地图层：

- `Modifier.fillMaxSize()`。
- 不要放在 Card 中。
- 不要有页面背景色露出。
- 地图作为第一层背景。

顶部返回按钮：

- 悬浮在地图上。
- 使用当前项目已有 `SportBackButton` 或 `AppPageTopBar` 中的返回按钮视觉。
- 只显示圆形返回按钮，不需要标题占位。
- 左侧距离屏幕 `16dp`。
- 顶部使用统一状态栏安全区。
- 跑步中点击返回仍沿用当前逻辑：弹出“放弃本次跑步？”确认弹窗。

底部信息卡片：

- 悬浮在地图上层。
- `fillMaxWidth()`。
- 左右边距 `16dp`。
- 距离底部建议：

```text
navigationBarsPadding + 20dp ~ 28dp
```

- 圆角 `20dp`。
- 背景使用深色半透明：

```text
#111820 / #151E26
Alpha 0.92 ~ 0.96
```

- 可以加轻微阴影。
- 不使用纯白背景。

## 5. 实时地图组件

建议新增：

```kotlin
@Composable
fun AMapRunTrackingMap(
    points: List<RunTrackPointUiModel>,
    isTracking: Boolean,
    modifier: Modifier = Modifier
)
```

使用：

```kotlin
AndroidView
MapView
DisposableEffect
LifecycleEventObserver
```

生命周期要求：

- `MapView.onCreate(Bundle())`
- `MapView.onResume()`
- `MapView.onPause()`
- `MapView.onDestroy()`
- 不要每次重组重新创建 `MapView`。
- 页面销毁时释放地图。

高德隐私接口：

当前项目高德轻量版 AAR 中，地图 `MapsInitializer` 不暴露隐私接口，但定位 SDK 暴露：

```kotlin
AMapLocationClient.updatePrivacyShow(context, true, true)
AMapLocationClient.updatePrivacyAgree(context, true)
```

创建 `MapView` 前调用一次即可。

## 6. 地图 UI 配置

当前轻量版地图 `UiSettings` 可用方法较少。

建议配置：

```kotlin
map.uiSettings.setScrollGesturesEnabled(true)
map.uiSettings.setZoomGesturesEnabled(true)
map.uiSettings.setTiltGesturesEnabled(false)
map.uiSettings.setRotateGesturesEnabled(false)
```

如 SDK 支持，关闭不需要的控件：

```text
缩放按钮
指南针
比例尺
定位按钮
```

如果轻量版不暴露这些方法，不要强行调用不存在 API。

## 7. 实时轨迹绘制

轨迹点来自：

```kotlin
uiState.trackPoints
```

绘制规则：

- 过滤非法坐标。
- 过滤 `0.0, 0.0`。
- 有 1 个有效点：
  - 地图移动到该点。
  - 显示当前位置 Marker 或不显示 Marker 均可。
- 有 2 个及以上有效点：
  - 绘制绿色 Polyline。
  - 轨迹颜色：

```text
#22C55E
```

  - 线宽建议 `8f ~ 12f`。
  - 起点可以显示 Marker。
  - 最新点可以显示 Marker，表示当前位置。

实时更新策略：

- 轨迹点数量变化时更新地图。
- 历史轨迹点不是高频无限增长到不可控，第一版可以简单 `map.clear()` 后重绘。
- 不要在每次秒表刷新时重绘地图。应尽量只在 `trackPoints` 变化时更新。
- 可以用 `remember(points)` 或内部记录上一次点数量来避免重复绘制。

## 8. 地图跟随策略

跑步过程中：

- 当 `isTracking == true` 且有有效点时，地图镜头跟随最新点。
- 建议使用：

```kotlin
CameraUpdateFactory.newLatLngZoom(latestPoint, 17f)
```

或：

```kotlin
animateCamera(...)
```

第一版建议使用 `moveCamera`，避免动画频繁触发导致卡顿。

可选增强：

- 如果有效点数量达到 2 个，第一次可缩放到完整轨迹范围。
- 后续实时记录时跟随最新点。

不要本次实现：

- 手势拖动后暂停自动跟随。
- 重新定位按钮。
- 北向/运动方向旋转。
- 轨迹回放动画。

## 9. 坐标系说明

当前轨迹点来自 Android 原生 GPS，通常是 WGS84。

高德地图使用 GCJ-02。

本次仍先沿用当前方式直接绘制：

```kotlin
LatLng(latitude, longitude)
```

但需要预留统一转换入口：

```kotlin
private fun RunTrackPointUiModel.toMapLatLng(): LatLng
```

后续如果发现实时轨迹相对高德底图有偏移，再单独做 WGS84 -> GCJ-02 坐标转换。

本次不要扩展坐标转换，避免影响当前 GPS 距离统计和历史轨迹。

## 10. 底部信息卡片内容

底部卡片保留当前跑步页核心信息：

```text
当前距离
运动时长
平均配速
GPS 状态
开始 / 结束按钮
```

建议结构：

```text
┌──────────────────────────────┐
│          3.26 km              │
│          当前距离              │
│                              │
│  21:36          6'37"/km      │
│  运动时长        平均配速       │
│                              │
│ GPS 信号良好 · 息屏记录中       │
│                              │
│       [ 结束跑步 ]             │
└──────────────────────────────┘
```

视觉要求：

- 距离数字最大，白色。
- 单位 `km` 可以小一点。
- 时长和配速左右两列对齐。
- GPS 状态使用绿色或灰色，保持当前规则。
- 主按钮保持现有 `AppPrimaryButton / AppDangerButton` 风格。
- 卡片内容紧凑，不要撑满半屏。

推荐卡片高度：

```text
240dp ~ 300dp
```

根据按钮和权限提示可以适当调整。

## 11. 权限与错误状态

保留当前权限逻辑：

- 没有定位权限：按钮显示“开启定位权限”。
- 没有通知权限：按钮显示“开启通知权限”。
- GPS 未开启：显示当前错误文案。
- 跑步中返回：弹出放弃确认弹窗。

地图显示策略：

- 即使没有权限，也可以显示地图底图。
- 没有轨迹点时地图居中默认城市或中国区域即可。
- 不要因为没有权限就让页面变成纯深色空白。

## 12. 弹窗与返回逻辑

保留当前：

```text
跑步中点击返回
↓
弹出“放弃本次跑步？”
↓
确认后 stopWithoutSaving + onBack
```

不要改变：

- 结束跑步保存逻辑。
- 保存成功跳转轨迹详情页逻辑。
- 错误提示逻辑。

## 13. 视觉规范

整体风格：

- 地图全屏。
- 数据卡片深色半透明。
- 绿色强调色 `#22C55E`。
- 不出现大块纯白 UI。
- 不出现地图上方大片深色空白。
- 按钮风格继续复用当前 APP。

底部卡片应该像悬浮在地图上的运动控制面板，而不是普通表单页。

## 14. 性能要求

- 不要每秒因为时长变化就重绘地图覆盖物。
- 地图覆盖物更新应尽量绑定 `trackPoints` 变化。
- `MapView` 只创建一次。
- 页面销毁时释放。
- 第一版可以 `clear + redraw`，但不要在无轨迹变化时重复执行。

## 15. 测试要求

实现后执行：

```text
testDebugUnitTest
assembleRelease
```

真机 release 验证：

1. 安装 release APK。
2. 点击首页开始运动。
3. 进入户外跑步页。
4. 确认地图铺满全屏。
5. 确认底部数据卡片悬浮在地图上，距离底部有间距。
6. 点击开始跑步。
7. 走动或跑步一段距离。
8. 确认轨迹实时绘制在地图上。
9. 确认距离、时长、配速仍正常更新。
10. 点击结束跑步。
11. 确认保存后进入轨迹详情页。
12. 确认详情页地图预览仍可显示历史轨迹。

## 16. 验收标准

最终必须满足：

- `RunTrackingScreen` 地图铺满全屏。
- 跑步信息卡片悬浮在地图上层底部。
- 卡片距离底部有合理间距。
- 实时轨迹在地图上绘制。
- 跑步过程中地图跟随最新位置。
- 距离、时长、配速、GPS 状态显示正常。
- 开始/结束/权限按钮逻辑不变。
- 跑步中返回确认逻辑不变。
- 不修改 GPS 采集和距离计算逻辑。
- 不修改数据库。
- 不破坏 `RunTrackDetailScreen` 已完成的高德轨迹预览。
- debug 和 release 构建通过。
