# 首页今天优先与 UI 一致性收尾 实现提示词

请基于当前 Android 项目，后续对首页信息层级和全局 UI 一致性做一轮收尾优化。

本提示词只用于后续实现规划。实现时必须控制范围，不要顺带新增新的业务模块，也不要破坏已经完成的体重记录、运动记录、趋势图、目标设置、编辑删除等功能。

## 1. 当前背景

当前项目已有：

```text
首页 HomeScreen
首页体重卡片 WeightSummaryCard
首页运动卡片 ExerciseSummaryCard
体重详情页 WeightDetailScreen
体重趋势页 WeightTrendScreen
运动详情页 ExerciseDetailScreen
体重记录新增 / 编辑 / 删除
运动记录新增 / 编辑 / 删除
运动目标设置
日期选择器 ExerciseDatePicker
运动时长分钟滚轮 ExerciseDurationPicker
```

现在功能已经逐步完善，后续需要做两类优化：

```text
方向一：首页信息层级优化，形成“今天优先”
方向二：UI 一致性收尾，统一弹窗、按钮、列表和选择器视觉
```

建议分阶段实现，避免一次性改动过大。

## 2. 方向一：首页信息层级优化

### 2.1 目标

首页当前已有体重卡片和运动卡片，后续需要调整信息层级，让用户第一眼看到今天最重要的状态。

首页信息优先级：

```text
今天是否已记录体重
今天是否已运动
今日体重
今日距离
轻量记录入口
```

整体原则：

- 首页优先回答“今天完成了吗”。
- 今日体重和今日运动距离要比历史累计更突出。
- 历史累计、目标进度等信息可以保留，但不能抢今日信息的视觉优先级。
- 没有记录时不要显示 `0.00` 造成误解，应给出清晰空状态和轻量入口。

### 2.2 体重卡片优化

首页体重卡片需要突出：

```text
今天是否已记录体重
今日体重
最新体重
轻量记录入口
```

建议展示规则：

如果今天已记录体重：

```text
今日体重
77.40 kg
今日已记录
```

如果今天未记录，但有历史记录：

```text
今日体重
--.-- kg
今天还未记录
最新 77.40 kg
```

如果完全没有体重记录：

```text
今日体重
--.-- kg
记录第一条体重
```

要求：

- 今日体重是卡片主视觉。
- 没有今日记录时，不要用历史体重冒充今日体重。
- 最新体重可以作为辅助信息显示。
- 点击体重卡片仍进入体重详情页。
- 如需轻量入口，可以在卡片内显示弱化的“去记录”提示，但不要改变现有导航行为，除非单独实现快速记录入口。

### 2.3 运动卡片优化

首页运动卡片需要突出：

```text
今天是否已运动
今日距离
今日消耗
轻量记录入口
```

建议展示规则：

如果今天已运动：

```text
今日里程
5.20 km
今日已打卡
```

如果今天未运动：

```text
今日里程
--.-- km
今日未打卡
去记录一次运动
```

要求：

- 今日距离是卡片主视觉。
- 今日未运动时不要显示 `0.00 km` 作为主值。
- 本周目标、本月目标、连续打卡等信息可以保留为辅助信息。
- 点击运动卡片仍进入运动详情页。

### 2.4 首页状态数据建议

可以扩展现有 UI State：

```kotlin
data class WeightCardUiState(
    val todayWeight: Double?,
    val hasTodayWeight: Boolean,
    val latestWeight: Double?,
    val latestDate: LocalDate?,
    ...
)
```

```kotlin
data class ExerciseSummaryUiState(
    val todayDistanceKm: Double,
    val checkedInToday: Boolean,
    val todayCaloriesKcal: Int,
    ...
)
```

如果现有状态已经包含相关字段，优先复用，不要重复建一套状态。

UI 不直接查询数据库。

数据流保持：

```text
Room / DataStore
   ↓
ViewModel
   ↓
UiState
   ↓
HomeScreen
```

### 2.5 首页验收标准

最终首页应满足：

- 体重卡片能明确看出今天是否已记录体重。
- 运动卡片能明确看出今天是否已运动。
- 今日体重和今日距离是各自卡片最突出的信息。
- 无今日记录时展示 `--.--` 或轻量空状态，不误导为已有记录。
- 历史累计和目标信息作为辅助信息存在。
- 不破坏点击进入详情页的现有行为。

## 3. 方向二：UI 一致性收尾

### 3.1 目标

对当前 APP 中已经完成的弹窗、按钮、列表、选择器做一次统一整理。

统一对象包括：

```text
所有弹窗输入框
所有按钮
体重详情页列表行
运动详情页列表行
日期选择器
时长选择器
目标弹窗
```

目标是让用户感知为同一套设计系统，而不是每个功能各有一套样式。

### 3.2 弹窗输入框统一

统一以下弹窗中的输入框：

```text
体重记录弹窗
目标体重弹窗
运动记录弹窗
运动目标弹窗
```

要求：

- 输入框高度一致。
- 圆角一致。
- 背景色一致。
- 边框颜色一致。
- 获取焦点时的强调色一致。
- Label、正文、错误提示字号一致。
- 错误提示位置和颜色一致。

建议抽取：

```kotlin
@Composable
fun AppInputField(...)
```

或者在现有组件基础上统一封装。

不要让每个弹窗单独写一套 `OutlinedTextField` 样式。

### 3.3 按钮统一

统一以下按钮：

```text
主按钮
次按钮
危险按钮
图标按钮
返回按钮
底部操作按钮
弹窗确认 / 取消按钮
```

要求：

- 同级按钮高度一致。
- 圆角一致。
- 横向间距一致。
- 主按钮使用绿色强调色。
- 次按钮使用深色背景 + 绿色描边或弱化绿色文字。
- 删除按钮使用统一危险色。
- 按钮文字字号和字重一致。

优先复用现有：

```text
AppPrimaryButton
AppSecondaryButton
AppDialogButtonRow
AppBackButton / SportBackButton
```

如果现有组件不足，可以补充：

```kotlin
AppDangerButton
AppIconButton
```

不要在各个页面继续手写零散按钮样式。

### 3.4 详情页列表行高统一

统一：

```text
WeightRecordRow
ExerciseRecordItem
```

要求：

- 行高接近一致。
- 上下 padding 一致。
- 分割线颜色和透明度一致。
- 日期列、主数值列、变化/辅助信息列的对齐逻辑清晰。
- 长按弹出操作弹窗不受影响。
- 文本不要因为中英文、单位长度变化而错位。

建议抽取共享尺寸常量：

```kotlin
RecordRowMinHeight
RecordRowVerticalPadding
RecordDividerColor
```

### 3.5 日期选择器视觉统一

统一：

```text
体重记录日期选择
运动记录日期选择
```

当前已经复用 `ExerciseDatePicker` 时，应继续统一维护。

要求：

- 深色背景一致。
- 当前日期和选中日期样式一致。
- 月份切换按钮样式一致。
- 日期格子点击区域一致。
- 不出现取消 / 确定按钮。
- 点击日期后立即选择并关闭。
- 点击外部关闭且不改变原选择。

### 3.6 时长选择器视觉统一

运动时长选择器继续保持分钟滚轮。

要求：

- 与日期选择器、目标弹窗保持同一深色视觉语言。
- 中心选中态使用绿色强调色。
- 上下未选中项透明度层级稳定。
- 选择器背景、圆角、内边距与其他弹窗协调。
- 不要增加确认按钮。

### 3.7 目标弹窗视觉统一

统一：

```text
目标体重弹窗
运动目标弹窗
```

要求：

- 标题位置一致。
- 输入区域间距一致。
- 单位展示方式一致。
- 保存 / 取消按钮高度一致。
- 错误提示样式一致。
- 点击外部关闭逻辑一致。

### 3.8 统一设计常量建议

可以整理到现有 Theme / components 中：

```kotlin
val AppDialogCornerRadius = 20.dp
val AppInputHeight = 56.dp
val AppButtonHeight = 52.dp
val AppButtonCornerRadius = 8.dp
val AppSectionSpacing = 16.dp
val AppFieldSpacing = 12.dp
val AppRecordRowMinHeight = 56.dp
```

命名应结合当前项目已有风格。

不要为了统一常量进行大规模无意义重构，只抽取真正重复使用的尺寸和颜色。

### 3.9 UI 一致性验收标准

最终应满足：

- 所有弹窗输入框高度一致。
- 所有同级按钮高度一致。
- 主按钮、次按钮、危险按钮视觉统一。
- 体重记录列表和运动记录列表行高接近一致。
- 日期选择器在体重和运动场景中表现一致。
- 时长选择器与整体深色运动风一致。
- 目标弹窗和记录弹窗不像两套 UI。
- 不修改已经完成的业务逻辑。

## 4. 推荐实现顺序

建议分阶段执行：

```text
阶段一：首页今天优先状态梳理
阶段二：首页体重卡片展示优化
阶段三：首页运动卡片展示优化
阶段四：抽取或统一输入框组件
阶段五：统一按钮组件
阶段六：统一列表行高和分割线
阶段七：统一日期 / 时长 / 目标弹窗视觉
阶段八：编译和回归验证
```

每个阶段完成后都需要编译验证。

## 5. 本提示词范围限制

后续根据本提示词实现时，不要顺带修改：

- 数据库 Schema
- 打包脚本
- APP 图标
- 体重趋势图核心算法
- 运动目标存储逻辑
- 运动记录热量计算逻辑
- 已完成的导航逻辑

如果确实需要调整共享组件，应确认所有调用方视觉不被破坏。
