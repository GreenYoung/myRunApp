# 体重记录编辑/删除 + 运动记录编辑 实现提示词

请基于当前 Android 项目，只实现以下功能：

```text
体重记录编辑
体重记录删除
运动记录编辑
```

不要修改已经完成的首页卡片、体重曲线、运动目标、运动日期选择、运动时长选择、APP icon、顶部栏等无关功能。

## 1. 当前背景

当前项目已有：

```text
体重记录新增
体重详情页
体重记录列表
运动记录新增
运动记录删除
运动详情页
ExerciseDatePicker
ExerciseDurationPicker
Room + Flow + ViewModel 架构
```

运动记录已经支持：

```text
长按记录
弹出删除确认弹窗
点击删除
删除该记录
```

本次需要在现有能力上补齐编辑和体重记录删除。

## 2. 实现范围

本次只实现：

```text
WeightRecord 编辑
WeightRecord 删除
ExerciseRecord 编辑
```

不要实现：

```text
批量删除
滑动删除
撤销删除
云同步
导入导出
运动记录复制
体重记录分享
新的统计页面
新的目标体系
```

## 3. 体重记录编辑

在 `WeightDetailScreen` 的体重记录列表中，长按某条体重记录后弹出操作弹窗。

操作弹窗建议包含：

```text
编辑
删除
```

点击“编辑”后：

```text
打开当前已有的记录体重弹窗
回填该条记录的日期
回填该条记录的体重
```

用户修改后点击保存：

```text
更新原记录
```

如果当前数据库使用日期作为主键或唯一键，需要注意：

```text
如果修改日期，需要避免产生重复日期冲突
如果目标日期已经有记录，应给出明确提示，或者按当前业务规则覆盖
```

优先保持当前项目已有的体重保存规则。

## 4. 体重记录删除

在体重记录操作弹窗中点击“删除”后，需要弹出二次确认。

确认弹窗建议展示：

```text
删除体重记录
2026-08-25 · 77.40 kg
```

点击确认删除后：

```text
删除该条 WeightRecord
关闭弹窗
列表和首页体重卡片自动刷新
体重曲线自动刷新
```

删除操作必须通过 ViewModel 调用 DAO。

Composable 不直接访问数据库。

## 5. 运动记录编辑

运动记录当前已经支持长按删除。

请将长按后的弹窗升级为操作弹窗，包含：

```text
编辑
删除
```

点击“删除”继续保持当前已有删除逻辑。

点击“编辑”后：

```text
打开当前已有的增加运动记录弹窗
回填原记录数据
```

需要回填：

```text
运动日期
运动场景
里程
运动时长
坡度（如果有）
```

当前 `ExerciseRecordEntity` 如果还没有保存坡度字段，需要先检查现有数据结构。

如果当前数据库没有坡度字段：

```text
不要为了编辑强行补复杂迁移，除非已经确认需要保存坡度
可先回填为默认坡度 0 或空值
但保存后仍按当前项目已有热量估算逻辑处理
```

如果需要更完整保存坡度，应单独评估数据库 migration，不要在本次无确认情况下扩大范围。

## 6. 运动记录保存规则

编辑运动记录保存后：

```text
更新原 ExerciseRecord
不新增重复记录
配速仍由 durationSeconds / distanceKm 动态计算
热量仍按当前已有逻辑重新估算
首页运动卡片自动刷新
运动详情统计自动刷新
```

如果运动日期、里程、时长、类型变化，相关统计必须随 Room Flow 自动更新。

## 7. ViewModel 状态建议

体重模块可以增加类似：

```kotlin
editingWeightRecord: WeightRecordItem?
pendingDeleteWeightRecord: WeightRecordItem?
```

运动模块可以增加类似：

```kotlin
editingExerciseRecord: ExerciseRecordUiModel?
pendingActionExerciseRecord: ExerciseRecordUiModel?
```

也可以使用更适合当前代码结构的状态命名。

原则：

```text
UI 只表达状态
ViewModel 负责业务动作
DAO 负责数据操作
```

## 8. DAO 建议

体重 DAO 需要支持：

```kotlin
deleteWeightByDate(date: String)
```

如已有主键 id，则按 id 删除。

运动 DAO 需要支持：

```kotlin
updateExercise(record: ExerciseRecordEntity)
```

或：

```kotlin
updateExerciseById(...)
```

优先采用当前项目 Room 代码风格。

## 9. UI 交互要求

长按记录后展示操作弹窗。

操作弹窗深色风格，与当前 APP 保持一致。

建议：

```text
标题：记录操作
按钮：编辑 / 删除
删除使用红色警示
编辑使用绿色强调
取消使用现有次级按钮风格
```

不要新增复杂菜单、底部 Sheet 或第三方组件。

## 10. 校验规则

体重编辑继续复用当前体重输入校验：

```text
日期合法
体重 30.00～300.00 kg
小数最多两位
```

运动编辑继续复用当前运动输入校验：

```text
运动日期合法
运动场景合法
里程 > 0 且 <= 500 km
运动时长必填，1～300 分钟
坡度合法
```

非法输入不写入数据库。

## 11. 数据刷新

所有修改和删除都必须通过：

```text
Room
↓
Flow
↓
ViewModel
↓
UI
```

自动刷新。

用户不需要重新进入页面或手动刷新。

## 12. 实现步骤

请按以下顺序执行：

```text
1. 阅读当前 WeightDao / ExerciseDao

10. 实现体重删除确认
11. 运动记录长按弹窗增加编辑入口

```

最终必须满足：

