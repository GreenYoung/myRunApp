# MyRunApp 后续优化路线

当前 APP 的运动打卡和体重记录基础功能已经基本完善。后续优化建议按投入产出和功能闭环优先级推进。

## 1. 记录编辑能力

运动记录目前支持新增和删除，建议补充编辑能力。

建议交互：

```text
长按运动记录
↓
弹出操作菜单
↓
编辑 / 删除
```

编辑可以复用当前“增加运动记录”弹窗，并回填：

```text
运动日期
运动类型
里程
运动时长
坡度
```

保存后更新原记录，不新增重复记录。

## 2. 体重记录编辑和删除

运动记录已经支持删除，体重记录列表也建议补齐同等能力，避免误录后无法修正。

建议能力：

```text
长按体重记录
↓
编辑 / 删除
```

编辑体重记录时复用当前体重记录弹窗，删除时弹出二次确认。

## 3. 统计维度增强

运动详情页后续可以增加时间维度筛选：

```text
周
月
年
全部
```

每个维度下展示：

```text
累计里程
累计消耗
打卡天数
平均配速
单次最长距离
```

统计逻辑仍然应由 ViewModel / 数据层提供，Composable 只负责渲染。

## 4. 趋势图模块化

体重曲线已经比较复杂，建议后续拆成独立图表模块。

建议支持：

```text
7 天
30 天
90 天
全部
横屏全屏
点选查看具体记录
目标体重线
```

保持体重详情页主流程简洁，复杂图表交互放到独立页面或独立组件内。

## 5. 目标体系增强

当前运动目标只包含周 / 月里程，后续可以逐步增加目标反馈，不建议一次性堆太多目标类型。

优先建议：

```text
本周还差多少 km
本月还差多少 km
目标完成百分比
连续打卡天数
目标完成提醒
```

暂不优先增加：

```text
卡路里目标
运动时长目标
每周运动次数目标
AI 目标推荐
```

## 6. 首页信息层级优化

首页可以继续围绕“今天优先”优化。

建议突出：

```text
今天是否已记录体重
今天是否已运动
今日距离
今日体重
今日消耗
目标完成状态
```

无记录时应提供轻量入口，而不是展示过多空数据。

## 7. 数据备份

本地记录类 APP 建议增加导出 / 导入能力。

优先格式：

```text
CSV
JSON
```

建议先支持导出，再支持导入。导出内容包括：

```text
体重记录
运动记录
运动目标设置
目标体重设置
```

## 8. 本地通知提醒

可以增加本地提醒能力。

建议提醒：

```text
每日体重记录提醒
每日运动打卡提醒
周目标进度提醒
```

先做本地通知即可，不急于引入账号、云同步或服务端。

## 9. UI 一致性收尾

随着功能增加，需要做一轮 UI 统一整理。

重点检查：

```text
所有弹窗输入框高度一致
所有按钮圆角一致
所有按钮颜色层级一致
所有详情页顶部间距一致
所有列表行高一致
日期选择器、时长选择器、目标弹窗视觉统一
```

避免后续每个功能独立增加样式，导致视觉风格分裂。

## 10. 高级能力规划

基础功能稳定后，再考虑高级能力。

候选方向：

```text
Health Connect 接入
GPS 跑步记录
跑步轨迹地图
心率
步频
云同步
AI 运动总结
```

这些能力涉及权限、设备适配、数据同步和复杂交互，建议放在基础功能稳定之后。

## 推荐下一步

优先实现：

```text
体重记录编辑 / 删除
运动记录编辑
```

原因：

```text
这两个能力直接提升日常使用容错性
可以复用现有新增弹窗
实现成本可控
功能闭环明显
不会引入复杂外部依赖
```
