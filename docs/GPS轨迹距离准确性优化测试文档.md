# GPS 轨迹距离准确性优化测试文档

## 1. 测试背景

当前第一版 GPS 跑步记录已经支持：

```text
前台 GPS 记录
实时距离 / 时长 / 配速
结束后保存运动记录
保存轨迹点
Canvas 简化轨迹展示
```

实测发现距离存在明显虚高：

```text
测试时长：约 17min
实际慢走距离：约 400m
APP 记录距离：约 1.11km
```

记录距离约为实际距离的 2.8 倍，说明当前 GPS 点过滤策略不足，慢走和低速场景下 GPS 漂移被大量累计到了总距离中。

## 2. 测试目标

本测试文档用于验证后续 GPS 轨迹距离过滤优化效果。

目标：

```text
降低慢走 / 停顿场景下的距离虚高
减少 GPS 漂移点累计
保证正常跑步距离不要明显少记
验证起步阶段 GPS 热身是否有效
验证不同运动状态下距离、轨迹、配速是否稳定
```

## 3. 当前疑似问题

### 3.1 GPS 漂移点被累计

慢走或停顿时，GPS 点可能在当前位置周围跳动。

如果每次跳动都参与距离累计，就会出现：

```text
人没有移动很多
但 GPS 点来回漂移
距离持续增长
```

### 3.2 精度阈值过宽

当前第一版可能只过滤：

```text
accuracy > 30m
```

对慢走场景来说，30m 精度仍然太宽。

建议测试优化后：

```text
accuracy > 20m 丢弃
```

必要时进一步收紧到：

```text
accuracy > 15m 丢弃
```

### 3.3 缺少最小移动距离过滤

如果两点之间距离过小，例如：

```text
1m
2m
3m
```

这些点可能只是 GPS 抖动，不应全部累计。

建议测试：

```text
两点距离 < 4m 不累计
```

### 3.4 缺少低速漂移过滤

慢走或原地停顿时，瞬时速度很低。

如果 GPS 点低速漂移，也可能被当成真实移动。

建议测试：

```text
瞬时速度 < 0.35m/s 不累计
```

但需要注意：

```text
过滤太强会导致慢走少记
```

所以必须用慢走测试验证。

### 3.5 缺少 GPS 热身

刚开始定位的前 10～30 秒，GPS 精度可能不稳定。

建议测试：

```text
开始后前 10～15 秒只收点，不累计距离
```

## 4. 建议优化参数

第一轮建议使用偏稳的折中参数：

```text
GPS 热身时间：10 秒
最大有效精度：20m
最小累计距离：4m
最小有效速度：0.35m/s
最大有效速度：6m/s
```

如果慢走仍然虚高：

```text
最大有效精度改为 15m
最小累计距离改为 5m
GPS 热身时间改为 15 秒
```

如果慢走明显少记：

```text
最小有效速度降到 0.25m/s
最小累计距离降到 3m
```

## 7. 测试场景

```text
不要频繁停顿
结束后查看 APP 记录距离
```

```text
APP 距离接近 400m
建议误差控制在 ±15% 以内
```

可接受范围：

```text
340m ～ 460m
```


验证 GPS 漂移是否还会累计出明显距离。

测试方式：

```text

```

期望结果：

```text
前 15 秒原地等待不应累计明显距离
```

### 7.5 测试 E：停走混合

目的：

验证走走停停时，停顿阶段不会持续累计漂移距离。

测试方式：

```text

```

```text

```

```text

```

建议可接受范围：

```text
250m ～ 360m
```

```text

```

### 7.6 测试 F：高楼 / 遮挡环境

目的：

验证弱 GPS 环境下 APP 是否会过度累计漂移。

测试方式：

```text
选择高楼附近或树木较多区域
慢走 300m
观察距离和轨迹
```

期望结果：

```text
距离可能有误差，但不应严重虚高
轨迹如果漂移明显，APP 应过滤掉低质量点
```

建议：

```text
该场景不作为核心精度验收，只用于观察鲁棒性
```

## 9. 判定标准

### 9.1 必须通过

```text
慢走 400m：误差不超过 ±15%
正常跑步 1km：误差不超过 ±10%
原地静止 5min：距离不超过 30m
起步热身：前 10～15 秒不明显累计距离
结束后轨迹点能保存
轨迹详情页能显示简化路线
```

### 9.2 可接受但需记录

```text
高楼遮挡区域误差较大
GPS 状态偶尔变弱
轨迹线局部轻微抖动
```

### 9.3 不通过

```text
慢走 400m 记录超过 600m
静止 5min 记录超过 50m
跑步 1km 记录低于 800m 或高于 1.2km
轨迹出现大范围跳点
结束后无法保存运动记录
结束后无法保存轨迹点
```

## 10. 建议调参流程

### 10.1 如果距离仍然虚高

优先调整：

```text
accuracy 20m -> 15m
最小累计距离 4m -> 5m
GPS 热身 10s -> 15s
最大速度 6m/s -> 5m/s
```

### 10.2 如果慢走距离少记

优先调整：

```text
最小有效速度 0.35m/s -> 0.25m/s
最小累计距离 4m -> 3m
accuracy 15m -> 20m
```

### 10.3 如果跑步距离少记

优先调整：

```text
最大速度 5m/s -> 6m/s 或 7m/s
最小累计距离 5m -> 4m
```

### 10.4 如果起点漂移明显

优先调整：

```text
GPS 热身时间增加到 15s
开始后必须连续收到 2～3 个有效点再累计
```

## 11. 建议开发改动方向

后续代码优化建议集中在：

```text
RunLogic.kt
RunTrackingViewModel.kt
```

建议新增配置：

```kotlin
private const val GPS_WARMUP_SECONDS = 10
private const val MAX_ACCURACY_METERS = 20f
private const val MIN_DISTANCE_DELTA_METERS = 4.0
private const val MIN_VALID_SPEED_METERS_PER_SECOND = 0.35
private const val MAX_VALID_SPEED_METERS_PER_SECOND = 6.0
```

建议新增统计字段用于调试：

```text

有效 GPS 点数量
过滤点数量
当前 accuracy
当前瞬时速度
```

这些调试信息可以先不展示给普通用户，但便于真机验证。

## 12. 最终目标

经过优化后，第一版 GPS 跑步记录应达到：

```text
慢走不明显虚高
静止不持续涨距离
正常跑步不明显少记
轨迹线没有大范围跳点
距离、时长、配速符合用户直觉
```

本阶段目标不是达到专业运动手表级精度，而是先解决明显虚高问题，让日常慢走和跑步记录可信。
